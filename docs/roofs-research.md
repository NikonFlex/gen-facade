## 0. Что у нас сейчас (из репозитория)

- Вид крыши — один на дом (`HouseSpec.roof.kind`: flat/gable/hip/shed); скаты — нижняя огибающая полуплоскостей от стен (`genfacade/roof.py`, шапка модуля). Для контура не из 4 сторон и без частей крыша плоская, валидатор предупреждает `Rule.ROOF_FLAT`; в шапке `roof.py` прямо сказано: «для Г-, Т-образного нужен прямой скелет» [проверено: чтение `genfacade/roof.py`].
- Части дома — прямоугольные крылья (`Plan.wings`, `WallRun.part`), у каждого своя крыша вида дома и свой карниз; крыши частей целые, свес верхней нависает над нижней (gf#412, 10.11) [проверено: `docs/tasks/gf-0412.md`].
- Решение «прямой скелет — не сделан» записано в gf#320 и gf#322, «Что осталось» [проверено: `docs/tasks/gf-0320.md` стр. 68, `docs/library-catalog.md` разд. «Крыши»].
- Доли видов у российских ИЖС (API строим.дом.рф, 43 630 проектов): двускатная 51,4 %, вальмовая 35,2 %, комбинированная 7,0 %, плоская 2,7 %, многощипцовая 2,4 %, односкатная 1,3 %; четыре вида модуля = 90,7 % [проверено: `docs/library-catalog.md`, замер 07.11]. То есть сложные крыши (комбинированная + многощипцовая) — 9,4 % проектов; остальное — один вид на дом.
- Реальный тест: 5 домов с поперечным фронтоном, дормером или мансардой, 2 дома с видом, который не строится (гамбрел, бабочка) [проверено: `docs/library-catalog.md`].
- Модель шага 4 крышу не видит: стена — силуэт до карниза; в `parts.sub_sheets` каждая часть — отдельный лист.

## 1. Процедурные крыши по контуру (straight skeleton)

Идея: крыша — «поверхность, по которой вода стекает к контуру». Прямой скелет (straight skeleton, SS) многоугольника плана даёт линии конька, вальмы и ендовы; высота точки скелета = расстояние до контура × tg(уклона). Взвешенный SS (weighted, WSS): у каждого ребра контура свой множитель скорости = свой уклон; вес, дающий вертикальную стену, = щипец (gable), нулевой/малый уклон ребра = плоское.

## 3. Представление крыши для модели

Варианты и что проще встроить:

1. **Граф плоскостей/рёбер (Roof-GAN, RoofDiT).** Свободная геометрия, но валидность нужно доказывать отдельно (геометрическая сходимость скатов, водоотведение). Много данных нужно (Roof-GAN — 502 дома). Для нас избыточно: фасадам нужны высота конька над стеной и форма щипца, а не любой граф.
2. **Последовательность токенов, как у стен.** Крыша = список скатов: (номер ребра контура, уклон, тип «скат/щипец/вальма/свес»), в порядке обхода контура. Совместимо с токенизатором и nanoGPT шага 4. Но длина зависит от числа вершин контура, контур входит в условие.
3. **Параметры по частям: (тип, уклон, направление конька) на часть.** Ближе всего к текущему коду: `HouseSpec.roof` становится списком по `wings`; геометрию даёт код (как сейчас). Покрывает комбинированную и многощипцовую (9,4 % российских проектов), но не ендовы между не прямоугольными частями и не гамбрел.
4. **WSS с весами рёбер контура как «параметры крыши».** Модель/правила выбирают на каждое ребро контура: вес (уклон) и режим (скат, щипец=вертикально/очень крутой, свес), а геометрию (коньки, вальмы, ендовы сами) даёт скелет. Сложные крыши (ендова, конёк из конька, Н-образный дом) получаются **по построению**, фасады сходятся на углах, потому что высота над углом одна. Это естественное продолжение «главной идеи» (параметры общие → фасады сходятся). Ограничение: нужна взвешенная реализация (CGAL) либо своя реализация поверх shapely; щипец — вертикальная грань, WSS её не даёт (веса положительные), её надо моделировать как особый режим (вес «очень большой» плюс срез) или отдельным шагом.

Что проще: п. 3 + п. 4 в связке — части дома (уже есть) + веса/режимы на рёбра контура части. Модель видит план целиком, если вход — дом целиком (контур, части, этажность, карнизы), а не стена.

## 5. Синтетика

- **Контур:** случайный ортогональный многоугольник из 2–5 прямоугольных крыльев (уже есть `synthetic` с одно-/двухуровневыми частями; П-, Н-, Т-, Г-, У-образные — это разные склейки крыльев).
- **Правила сочетания частей:** для каждой части свой тип из {gable, hip, shed, flat}; конёк вдоль длинной стороны части (как у нас сейчас `ridge_along_longest`); пересечение двух двускатных крыш под прямым углом даёт ендову, одинаковые уклоны — конёк упирается в конёк; нижняя часть под верхней — скат к стене верхней (уже есть в `_off_walls`).
- **Веса:** случайные уклоны на часть из диапазона реальных (двускатная 32–45°, вальмовая 22–33° [проверено: `docs/library-catalog.md`]); для плоской середины П/Н-образного дома — flat у средней части, скатные у крыльев.
- **Эталон:** процедурный генератор (вариант а) — это и есть синтетика: «эталон = код по правилам», модель учится воспроизводить выбор (какие веса/типы), как шаг 4 учится раскладке.
- **Валидатор:** любой дом, у которого скаты не сходятся/вода не стекает, отбрасывается (в WSS это выполняется по построению).
- Ограничение синтетики: «правила сочетаний» — наши, без реальных распределений; реальные крыши из OSM/LoD2/3D BAG нужны, чтобы проверить распределения и показать разрыв «синтетика → реальные дома» (в тексте ВКР это уже запланировано схемой «ОБУЧЕНИЕ И ОЦЕНКА»).

## 6. Варианты встраивания

**(а) Код по правилам: тип и уклон на ребро контура/часть + взвешенный SS; параметры — из шага 1 (текст) и общих правил.**
- Токены: не меняются; `HouseSpec.roof` из одного вида в список по частям (или вид + уклоны по рёбрам).
- GPU и переобучение: нет.
- Что даёт на защите: сложные крыши и П/Н/Г/Т-образные дома без новой модели; согласуется с «главной идеей» (параметры общие → фасады сходятся по построению); но новизна — только в связке с фасадами, не в крыше.
- Объём: задача среднего размера — своя реализация SS поверх shapely или обёртка CGAL (лицензия — решение хозяина); новые параметры в `schema`; `roof.py` (588 строк) переписать с «огибающей полуплоскостей» на скелет; тесты и 3D; валидатор ROOF_FLAT снять для контуров из частей.
- Минус: выбор уклонов — эвристика; слуховые окна и ендовы кроме ортогональных — отдельная работа.

**(б) Мини-модель крыши (шаг 1б): вход — план целиком (контур, части, этажность, карнизы); выход — тип и вес на каждое ребро/часть.**
- Токены: новая последовательность (≈ n_частей × 3 значения: тип, уклон, ось конька); отдельный словарь, отдельный чекпойнт; крохотная модель (на порядок меньше 10,8M) — оценка [не проверено].
- GPU: учить можно на CPU или одном GPU за минуты; переобучать только её.
- На защите: модель, которая видит дом целиком и выбирает крышу; сравнение с правилами (а) как базовой линией и ablation «крыша от одного вида на дом / по правилам / по модели» — прямо ложится в пять групп метрик и ablation ТЗ Валерии; но настоящих данных для обучения мало (реальные: OSM, LoD2, около 59 размеченных домов), поэтому модель обучается на синтетике правил из п. 5 — риск «модель выучила наши правила».
- Объём: большой — (а) обязателен как база; плюс датасет, обучение, метрики.

**(в) Расширить модель шага 4 токенами дома целиком (контекст: части, крыша по частям).**
- Токены: в начало последовательности — токены дома (части, их контуры, высоты, крыша), затем стена; либо префикс из всех частей и крыш; длина последовательности растёт.
- GPU: да, переобучение 10,8M целиком; прежние чекпойнты не совместимы.
- На защите: сильнее всего по теме («модель видит дом, а не стену» — прямой ответ на замечание хозяина), но дороже и рискованнее: меняется контракт токенов (строго по `docs/agents/`), ломается обратная совместимость с gf#107 и стабом; крыша в токены стены не входит, поэтому польза для крыши — косвенная (модель увидит, какая крыша над стеной, и учтёт запретные зоны/скаты).
- Объём: самый большой.

## 7. Рекомендация

1. Сначала (а) с отдельной задачей: части дома (уже есть) + тип/уклон по части + **скелет над контуром части**; для общего контура (Н-, П-образный, ендовы) — взвешенный SS, 4 вида модуля остаются как режимы. Дом целиком модель увидит через `HouseSpec` (параметры по частям), а не через стену — вход шага 4 не меняется.
2. Затем (б) как мини-модель по тем же параметрам: честно сравнить с правилами, ablation, реальные дома для проверки. (в) — только если (б) покажет, что модели стены нужен контекст дома: сначала замерить, сколько отказов валидатора у стены связано с крышей.
3. Первый шаг: прототип на shapely-polyskel (или самописном скелете) на тестовых контурах Г/Т/П/Н — проверить, что получаются коньки и ендовы, и сверить с тремя 3D-снимками ffh-mae/annex-2 из gf#412. Заодно открыть https://github.com/scikit-geometry/scikit-geometry и проверить, есть ли там взвешенный SS (`skgeom.skeleton`), и решить вопрос лицензии (CGAL — GPL?, polyskel LGPL, bpypolyskel GPL) с хозяином до кода.
4. Данные: вытащить из OSM `building:part` с `roof:shape` по нескольким регионам для проверки распределений синтетики; 3D BAG / LoD2 Германии (DL-DE) — для реальных составных крыш. Building3D (CC BY-NC-SA, регистрация) — для каркасов.
