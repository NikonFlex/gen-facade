# Подходы к генерации векторного фасада

Обновлено: 2026-09-25

## Два пути и почему выбор непростой

### Путь A — генерация напрямую в векторе

Описание → структурное представление фасада (примитивы, классы, координаты, иерархия,
связи) → SVG. Модель работает сразу над геометрией, а не над пикселями.

Что предлагают в качестве архитектур:

- по описанию Валерии: трансформеры над последовательностью примитивов, графовые модели
  над связями элементов, в духе DeepSVG и FloorplanGAN
- по совету Егора: **LLM-модели**, генерирующие SVG как текст

Плюсы: геометрия и структура в модели «из коробки»; результат сразу редактируемый;
попадает в формулировку темы дословно.

Минусы: нужен датасет в векторном/структурном виде, которого может не быть
(см. [datasets.md](datasets.md)); 606 примеров CMP — крайне мало для обучения с нуля;
риск не дойти до рабочего результата.

### Путь B — растр, затем векторизация

Описание → растровый фасад (диффузионная модель) → векторизация (DiffVG / LIVE / EvoVec)
→ SVG. Это архитектура GenPlan, перенесённая на фасады.

Плюсы: опирается на предобученные диффузионки, то есть проблема малого датасета
частично снимается; Егор это уже делал и сможет помочь (EvoVec — его статья);
почти гарантированно даёт работающий результат.

Минусы: сам по себе — применение готовых инструментов к новому домену, слабая новизна
для темы «разработка метода»; и главное — см. ниже.

## Ключевая проблема пути B, и где из неё вырастает тема

**DiffVG, LIVE и EvoVec структурно-агностичны.** Они приближают пиксели кривыми и
ничего не знают про фасад: что окно второго этажа должно стоять ровно над окном первого,
что этажи повторяются с постоянным шагом, что проёмы выровнены по вертикальным осям,
что линии параллельны.

Прогнав рендер фасада через готовый векторизатор, получим красивый SVG, который
**не является чертежом**: окна чуть разного размера и слегка сдвинуты, кривые вместо
прямых, число примитивов не соответствует числу архитектурных элементов.

Отсюда гипотеза о вкладе работы:

> **Структурно-осведомлённая векторизация фасадов** — заложить в процесс векторизации
> (или в пост-обработку/оптимизацию) априорное знание о решётчатой структуре фасада:
> регулярность сетки этажей и осей, повторяемость элементов, выравнивание, параллельность.

Почему это удачно ложится:

- попадает в экспертизу Егора → будет реальная помощь и соавторство
- попадает в формулировки Валерии: «сохранение геометрической структуры, повторяемости
  элементов и архитектурной согласованности», «корректность геометрии», «корректность
  структуры», «доля валидных векторных документов»
- даёт естественный ablation: обычный векторизатор vs векторизатор со структурными
  ограничениями
- не требует отказа от пути B, то есть риск «ничего не заработало» низкий

**Предлагаемая стратегия: B как каркас пайплайна, A как то, что добавляется внутрь.**
Это буквально и есть «отдельный метод, применимый к моей работе» из слов Егора.
Решение пока не зафиксировано — см. [decisions.md](decisions.md).

## Формальное представление фасада

Требуется по ТЗ. Пока не проработано. Что нужно определить:

- геометрические примитивы (прямоугольник? полигон? кривая Безье?)
- классы элементов (можно взять 12 классов CMP)
- координаты и размеры, система координат и нормализация
- пространственные связи между элементами
- иерархия: фасад → этаж → элемент
- описание повторяемости (сетка, шаг, группы)

Здесь же решается, что подавать на вход модели и в каком виде считать метрики структуры.

## Векторизация: кандидаты

Сравнить, прежде чем выбирать. Подробнее — [papers.md](papers.md).

| Метод | Идея | Статус |
|---|---|---|
| DiffVG | дифференцируемый растеризатор, оптимизация SVG по градиенту | не изучен |
| LIVE | послойная векторизация, наращивание примитивов | не изучен |
| EvoVec | эволюционная, адаптивное число кривых, работает с градиентами | не изучен, статья Егора |

## Генерация растра: кандидаты

- Stable Diffusion XL — то, что используется в GenPlan `[проверено: README GenPlan]`
- Современные диффузионные модели — Егор советует «почитать про диффузионки
  и современные модели», конкретику не дал
- Условная генерация: ControlNet / LoRA-файнтюн на фасадах, управление числом этажей
  и типами элементов (требование ТЗ)

## GenPlan — референсная архитектура

https://github.com/CTLab-ITMO/GenPlan · лаборатория CTLab ITMO

Тот же пайплайн, но для **планировок квартир**, а не фасадов. Из README `[проверено: README]`:

- текст → генерация изображения (SDXL, есть параметр «white loss») → препроцессинг →
  векторизация → оптимизация → экспорт
- выход 2D: SVG; выход 3D: IFC, OBJ, glTF, GIF
- управляемость: опционально задаются координаты контура
- модули: `decorator/`, `dto/`, `generator/`, `preprocessor/`, `vectorization/`,
  `optimizer/`, `three_dimensional/`, `metrics/`, `textures/`
