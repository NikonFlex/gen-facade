## Предложено в документе впервые (решения студента, согласовать)

- Согласованность четырёх сторон **по построению**: общие параметры дома
  (этажность, высоты, крыша, материалы) на весь дом, элементы — по сторонам;
  силуэт крыши и фронтона вычисляется из параметров и контура плана.
- Запретные зоны на стороне — места примыкания внутренних стен; окно туда
  не ставится (дефект «стена приходит в окно»).
- Разбор текста в спецификацию дома отдельным шагом — закрывает пункт ТЗ
  про условную генерацию по параметрам.
- Три кандидата архитектуры: дообученная LLM, свой трансформер, диффузия
  над множеством элементов с графом отношений (пункт ТЗ «на основе графов»).
- Метрики: пять групп ТЗ + согласованность с планом + соответствие описанию.
- Стадии 0–9 без дат: сроки неизвестны, спрашиваем.

## Новизна: поиск литературы 28.09

Агент прогнал ~30 запросов (англ. + рус., arXiv API, OpenAlex); отчёт
и перепроверка — в `docs/papers.md`, раздел «Фасады по плану».
Лично перепроверено `[проверено: страницы arXiv / сайт]`:
- **ShellMaker** (ECCV 2026) — стены с заданными проёмами + текст → 3D-оболочка;
  проёмы не ставит, этажей не различает (§4.7), код обещан, не выложен;
- **ArchyBase** — коммерческий: план → 4 фасада, экспорт SVG/DXF, метода нет;
- **GeoTexBuild** — контур → 3D, проёмов нет;
- **Text2BIM** — цитата про трудность расстановки проёмов для LLM (подпись к рис. 12);
- **ProxyBuild** — текст → структурированное 3D; утверждение агента, что модель
  ставит окна сама, по аннотации **не подтвердилось**, в документ не пошло.

Вывод: заявлять «первыми делаем фасады по плану» нельзя (ArchyBase); свободно
сочетание — воспроизводимый метод, векторный план + текст → четыре согласованных
векторных фасада, два режима, метрики согласованности.

Поправлено при вычитке: у GenPlan стены не «одного цвета», а с одной
текстурой на весь дом (`three_dimensional/convertor.py:468` вызывает
`apply_wall_texture`); год Text2BIM убран — не проверял.
