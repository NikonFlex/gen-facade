## Описание из трекера

Переписка с научруками идёт в Telegram, вставлять её в чат с Claude руками неудобно.
Хозяин пересылает пачку сообщений в тему «Входящие» своей группы с темами; бот её забирает,
отсекает уже виденное и складывает в буфер, откуда навык `/inbox` (отдельная задача) делает
файл во `docs/incoming/`.

Группа — только хозяин и бот (в «Разборе» будут заметки, которые научрукам не показывать).
Темы: 📥 Входящие, 🧾 Разбор, ❓ Вопросы научрукам, ✅ Задачи и PR, 🖼 Результаты.

Что сделать:
- `tools/tg_inbox.py`:
  - `pull` — `getUpdates` с `offset`, берёт только сообщения из группы и темы «Входящие»
    и только от хозяина, остальное молча отбрасывает;
  - отсев повторов по ключу «исходный автор + исходная дата + хэш текста»: исходного
    `message_id` у пересылки от человека Bot API не отдаёт;
  - вложения (PDF, картинки) — в буфер идут `file_id`, имя и размер, без самого файла:
    раннер Action файлы не хранит, а чужие PDF в git не кладутся; скачивает `/inbox`
    (gf#83) вне git;
  - ответ в теме: «принял N, новых M, повторов K»;
  - `--discover` — id группы и номера тем; проба отправки в тему.
- Буфер — JSONL в отдельной ветке `tg-inbox`: в истории `main` его нет и CI на нём не бежит.
- GitHub Action по расписанию, раз в час, вызывает `pull` и коммитит буфер. Без этого
  сообщения пропадут: Telegram хранит необработанные апдейты не дольше 24 часов.
  У Action есть и ручной запуск (`workflow_dispatch`): им `/inbox` (gf#83) забирает новое
  сразу, не дожидаясь расписания. Буфер пишет только Action — второго писателя нет.
- Токен, id группы и номера тем — в `.env` и секретах репозитория, не в коде; `.env.example`
  получает имена переменных.
- Тест с подставным сервером через `TELEGRAM_API_BASE`, без сети.

От хозяина: бот в BotFather, группа с включёнными темами и пятью темами, бот — админ
(или выключенная приватность), токен в `.env` и секреты репо.

Готово, когда:
- `python3 tools/tg_inbox.py --selftest` (входит в `tools/check.sh`) проходит на
  подставном сервере: пачка из 5 пересланных
  сообщений, из них 2 повтора прошлой пачки → в буфере 3 новых, ответ «принял 5, новых 3,
  повторов 2»; тест краснеет, если сломать ключ отсева;
- сообщение не от хозяина или из другой темы в буфер не попадает (тест);
- `tg_inbox.py --discover` на живом боте печатает id группы и номера пяти тем;
- живая пересылка пачки во «Входящие» → не позже чем через час в ветке `tg-inbox` новый
  коммит с этими сообщениями, а в теме — ответ бота;
- `gh workflow run` вручную → новый коммит в `tg-inbox` с пересланным, не дожидаясь
  расписания; время от запуска до коммита записано в задаче;
- без токена `pull` пишет предупреждение и выходит с кодом 0;
- в `README.md` — настройка: бот, группа с темами, `.env`, секреты репо, `--discover`.

Датчик: число сообщений в буфере после прогона на тестовой пачке.
