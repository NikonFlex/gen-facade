## Описание из трекера

Хозяин 08.10. Новый порядок, когда задача сделана:

1. Локально — только нужные тесты: те, что затрагивает изменённый код (готовый инструмент —
   `pytest-testmon`), и быстрые проверки (ruff, спеки, пути). Хук перед `git commit` —
   тот же быстрый набор.
2. Всё зелёное — PR. На CI — полный `tools/check.sh`.
3. CI зелёный — PR сливается автоматически: задача в CI после полного прогона (репозиторий
   приватный, защита ветки на бесплатном тарифе недоступна); станет публичным — встроенный
   автомердж GitHub с обязательной проверкой.
4. **Ни в PR, ни в коммитах — слов, по которым GitHub закрывает задачу** (close, fix, resolve
   во всех формах рядом с номером). Ссылка — «Задача gf#12». Задачу закрывает только хозяин
   своим словом. Проверка в CI и хуке не пропускает такое слово.
5. Метрика рядом с FPSR — сколько PR понадобилось задаче: все PR со ссылкой на задачу,
   включая закрытые без слияния. В `/fpsr` и `/catchup`.

Готово, когда:

- `CLAUDE.md` и `.claude/rules/` описывают новый порядок, `Closes` нигде не советуется;
- хук перед `git commit` запускает быстрый набор: тесты по `pytest --testmon` (на подложенной
  ошибке в модуле краснеет его тест, остальные не запускаются) — замер времени до/после;
- CI на PR: полный прогон, затем автомердж; проверено на настоящем PR;
- проверка закрывающих слов краснеет на «Closes #12» в коммите и в описании PR и молчит на
  «Задача gf#12»;
- `python3 tools/fpsr.py` показывает PR на задачу (gf#76 — 2: #77 и #80);
- `sh tools/check.sh` проходит.
