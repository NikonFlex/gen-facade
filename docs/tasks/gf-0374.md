## Описание из трекера

Хозяин 09.11: «у нас должны тесты за минуту на коммит проходить… надоело ждать». Проверка перед коммитом (`tools/check.sh --quick`) гоняет только затронутые тесты (pytest-testmon), но база testmon (`.testmondata`) — своя у каждого рабочего дерева. В новом дереве базы нет — первый коммит гоняет все быстрые тесты (~10 мин); проверки идут по одной (`tools/hook_lock.sh`), и 09.11 шесть новых деревьев агентов дали очередь почти на час [проверено: `.testmondata` 4 КБ в свежем `diploma-356d`, очередь `hook_lock` из пяти коммитов]. Коммиты из одних `.md` стоят в той же очереди, хотя тестов для них нет.

Что сделать:
- новое дерево без `.testmondata` берёт базу из самого свежего `.testmondata` среди деревьев клона (`git worktree list`) — первый коммит гоняет только затронутое;

Готово, когда: первый коммит в новом дереве с правкой одного модуля проходит хук за 1–3 минуты, коммит из одних `.md` — без pytest; есть проверка, которая падает на прежнем поведении.
