## Что установлено: есть второй путь, возможно лучше

**IFC → семантический SVG-фасад работает** `[проверено: артефакты прогона агента
осмотрены лично]`. Команда:

```
IfcConvert дом.ifc out.svg --auto-elevation --scale 1:100 \
    --exclude entities IfcOpeningElement --svg-segment-projection -y
```

На FZK-Haus (реальный одноквартирный дом KIT) выдаёт четыре вида
Elevation East/North/South/West и **классифицированные прямоугольники
в настоящих метрах**:

```
IfcWindow  EG-Fenster-8   x=6.50  y=-2.00  w=2.00  h=1.20
IfcDoor    Haustuer       x=-5.50 y=-2.01  w=1.01  h=2.01
IfcSlab    Dach-1         x=-10.50 y=-6.32 w=5.50  h=3.41
```

Проверил сам: в выходных SVG 41 группа `projection IfcWindow`,
14 `IfcDoor`, 14 `IfcSlab`, в `structure.json` 103 элемента. Внутренние двери
на фасад корректно не попадают.

Три грабли, обойдены в скрипте агента (`scratchpad/cad/ifc/ifc2facade.py`):
`--auto-elevation` в одиночку даёт **пустой файл** (нужен `--exclude entities
IfcOpeningElement`); `--svg-without-storeys` ломает вывод; **без
`--svg-segment-projection` семантики нет вообще** — только безымянные пути.
Python API `ifcopenshell.draw` не заменяет CLI: поля `segment_projection` в нём нет.

Лицензия IfcConvert — **LGPL-3.0-or-later** (в корне лежат и `COPYING`, и
`COPYING.LESSER`, GitHub показывает GPL-3 — это про Bonsai). Как внешний бинарь
LGPL наш код не заражает.

**Чем этот путь лучше building_tools:** классы приходят из настоящей
архитектурной семантики IFC, а `data-guid` позволяет подтянуть к прямоугольнику
все свойства элемента (проверено: `OverallWidth=2.0, OverallHeight=1.2` сходится
с bbox). То есть ground truth получается детерминированно, без разметки и её шума.

**Чем хуже:** открытых IFC-моделей жилых домов **всего порядка 9**, из них
настоящих коттеджей 5–6. На обучение не хватит — это held-out для валидации.

**Вывод для этой задачи:** вероятно, правильная связка — не «building_tools →
SVG», а **свой процедурный генератор поверх `ifcopenshell.api` → IfcConvert →
размеченный SVG**. Объём даёт генератор, реальные 9 моделей уходят в held-out.
Кандидат на основу генератора — `hypar-io/Elements` (MIT, 418★), внутрь никто
не смотрел.

Отдельно: **открытого процедурного генератора зданий в IFC не существует**
(проверено поиском по GitHub) — то есть это самостоятельный вклад, а не костыль.

## Старт этапа 2, 01.10: рамки от хозяина и что даёт building_tools

**Рамки (хозяин 01.10):**
- сначала только коттеджи;
- крыша остаётся плоской: скатная на непрямоугольном контуре — отдельная сложная
  задача, и её трудно превратить в 3D; стена в данных — прямоугольник до карниза,
  синтетика — только с плоской крышей;
- датасеты будут собираться и лежать на другой машине (скорее всего Windows + WSL,
  какая — пока неизвестно); сначала учимся делать всё здесь локально, на малых
  объёмах. На этой машине свободно ~0.4 ГБ из 76 — большие данные сюда не кладём.

**Что building_tools даёт на самом деле** `[проверено: код аддона, коммит 0216534
от 2025-05-16, `btools/api/api.py`, `api/options.py`, `building/floorplan/floorplan_types.py`;
01.10 не запускал]`:
- контур плана пяти видов (прямоугольник, круг, крест, Н-образный, случайный
  с выступами) и выдавливание этажей;
- окно, дверь, балкон ставятся на **выбранную нами** грань с **нашими** параметрами
  (`ArrayOptions.count/spread`, `SizeOffsetOptions.size/offset`). Правил «где и сколько
  окон» в аддоне нет — рандомизатор раскладки в любом случае пишем мы;
- **внутренних стен и комнат нет** (поиск по коду `room`/`interior` — пусто), значит
  нет запретных зон и плана в формате GenPlan;
- зон отделки, цоколя, подоконников, карниза нет; материалы — группы граней для
  текстур Blender.

Вывод: при плоской крыше и стенах-прямоугольниках аддон приносит только форму
контура. Blender ради этого — тяжёлая зависимость (на той машине — WSL + Blender),
а раскладку, декор, зоны и внутренние стены всё равно делает наш код.

**Аддон стоит ненадёжно:** `~/.config/blender/4.0/scripts/addons/building_tools` —
симлинк в `/tmp/claude-0/…/4a935d1b…/scratchpad/blender/building_tools`, папку
прошлой сессии. Исчезнет — ставить заново.

### ProcTHOR-10k — готовые синтетические дома (AllenAI)

`[проверено 01.10: LICENSE и test.jsonl.gz из github.com/allenai/procthor-10k, разбор всех
1000 домов test, 12 случайных нарисованы и осмотрены — docs/assets/procthor-10k-sample.png]`
- Apache-2.0; test — 1000 домов, 5.0 МБ. train 53 МБ, всего 12 000 домов `[не проверено]`.
- JSON, метры: `rooms[].floorPolygon` + `roomType` (Kitchen, LivingRoom, Bedroom, Bathroom —
  прихожей и коридора нет); стены по комнатам и отдельно `wall|exterior|…`; окна и двери
  ссылаются на стену, `holePolygon` — положение вдоль стены и высота.
- Наружная дверь ровно одна в каждом из 1000 домов.
- Окон мало: 0 — 108 домов, 1 — 170, 2 — 248, 3 — 200, 4 — 126, 5 и больше — 148.
- Комнат: 1 — 213 домов, 2 — 174, 3 и больше — 613.
- Глазами: контуры ступенчатые (вырезы по углам), прямоугольных мало; комнаты крупные,
  сетка ~1.6–2.2 м; вход бывает в ванную или спальню; дом «спальня + ванная» — норма.
  Это планировки для роботов-симуляторов, а не архитектура.

### Генератор ProcTHOR (github.com/allenai/procthor)

`[проверено 01.10: LICENSE, floorplan_generation.py, interior_boundaries.py, utils/types.py,
GitHub API]` Apache-2.0; последний push 2023-04-07, не поддерживается. Этап планировки —
