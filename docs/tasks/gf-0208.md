## Описание из трекера

`tests/unit/test_sampling.py::test_layout_prompt_ends_with_answer_mark` падает везде, где стоит
torch (в CI torch нет, тест там не идёт): `pytest.raises(TokenError)` ждёт, что необученная
модель ответит мусором, а страж (`train/constraints.py`, gf#177, gf#197; `models.layout.constrain`
по умолчанию включён) делает её ответ разборчивым — DID NOT RAISE.

Тест проверяет главное — условие кончается `<answer>`. Поправить его, не подгоняя ожидание под
факт: «мусор» — с выключенным стражем; со стражем — то, что страж гарантирует (ответ разбирается).

Готово, когда: `.venv/bin/python -m pytest tests/unit/test_sampling.py` зелёный с torch, а тест
краснеет, если из условия (`Layout.prompt`) убрать `<answer>` или выключить страж в ветке «со стражем».

Без сценария — правка теста, поведение модуля не меняется.
