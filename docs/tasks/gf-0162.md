## Описание из трекера

ТЗ требует сравнения с базовыми подходами; из четырёх есть один — правило GenPlan (gf#141). LLM без
дообучения отвечает на вопрос «зачем вообще обучать свою модель», его спросят первым.

Что сделать:
- до кода — какую LLM и через что (ключ в `.env`, модель, цена запроса); готовые промпты и работы
  по генерации раскладки фасада/лейаута LLM без дообучения — найти и записать;
- промпт: условие дома (параметры, стены, проёмы плана, запретные зоны) в текстовом виде → ответ
  в нашем формате (токены или JSON листа) → разбор → тот же лист; неразобранный ответ — `{"error": …}`;
- `genfacade baseline llm <папка листов> -o <папка>` на тех же домах, что модель, затем
  `genfacade metrics` — строка таблицы в обоих режимах;
- платные запросы: сначала сказать хозяину, сколько их будет и почём, прогнать на 1–2 домах; тесты —
  на заглушке, без сети.

`openspec/specs/evaluation/spec.md` — «Базовые подходы»

**Готово, когда:**
- строки «LLM без дообучения» в обоих режимах — в таблице `genfacade metrics` против того же эталона,
  что модель (число домов — по согласованию с хозяином из-за цены), в `docs/metrics-results.md` и в
  низу задачи;
- тест разбора ответа LLM на заглушке, красный на сломанном разборе.

Датчик: доля разобранных ответов LLM на первых 10 домах.

## 09.11 — код с заглушкой (ветка `162-llm-baseline`, не запушена)

Хозяин 09.11: «Сделаем заглушку. Потом, когда у меня лимитов побольше будет, запустим на нормальных моделях.
Сейчас мало токенов». Сделано без единого платного вызова; `.env` не открывался, ключи — только из переменных
окружения по имени из конфига.

- **Команда.** `genfacade baseline llm --provider <claude|openai|deepseek|stub> -o <папка> [-n <домов>]`: дома реального
  теста → промпт → ответ → разбор → `<папка>/<поставщик>/<режим>/model/<дом>.json`; каждый запрос записан в
  `<режим>/calls/<дом>-<n>.json` (дата, промпт, ответ, оценка токенов). Дом, чей лист уже лежит, не пересчитывается —
  оборванный платный прогон продолжается без повторных запросов. `--dry-run` печатает запросы, токены и цену по
  конфигу на каждого поставщика, ничего не вызывая.
- **Формат — токены, не JSON.** Условие и ответ — той же записью, что видит и выдаёт наша модель (`tokens.condition`,
  `tokens.answer`): ответ в 4–5 раз короче JSON листа, а разбор (`tokens.decode`), привязка и валидатор — те же
  шаги 4–5 `pipeline.layout`, куда LLM встаёт как «модель» того же интерфейса (`prompt`, `answers`, `path`);
  дом из частей разной высоты отвечает по частям, как модель. Повтор — по `[llm] attempts`, без текста ошибки
  в промпте (интерфейс модели его не передаёт; сэмплирование при температуре 0,7 даёт другой ответ, как у нашей).
  Отказ после попыток — `{"refusal": MODEL_NO_ANSWER, "attempts": …}` и «годных N/M» в таблице, как у модели.
- **Промпт**: правила записи, служебные токены, `[llm] shots` = 8 примеров из синтетики train (пул `pool` = 300
  домов по `seed`; ближайшие по числу сторон, этажей и периметру, тот же режим; реальные дома в пул не входят),
  затем дом: описание словами, условие режима словами, условие токенами, «Ответ:». Тексты — `[llm.prompt]`.
- **Поставщики.** `LlmProvider` в `schema.py` (claude, openai, deepseek, stub); модель, ключ-переменная, цена за
  млн токенов — `config/baselines.toml`, `[llm.providers.*]`. Клиенты `anthropic` и `openai` (DeepSeek — по
  `base_url`) подключаются, если библиотека есть в окружении; в venv проекта их нет (проверено 09.11:
  `import anthropic`, `import openai` — ModuleNotFoundError), зависимости не ставил — без библиотеки или ключа
  отказ `llm_unavailable`, до первой работы.
- **Заглушка.** Ответ `stub` — то, что ответило бы правило GenPlan, записью токенов: это не эталон и не результат,
  проверка пути «промпт → ответ → лист → realtest».
- Цены OpenAI и DeepSeek и их модели в конфиге — `[не проверено]` (сверить с прайсом перед запуском); Sonnet 5.5 —
  `[проверено]` 02.11 (см. выше).
- `pipeline.layout` и `realtest.answers` получили необязательный параметр `model` — своя модель того же
  интерфейса; ход обученной модели не менялся.
