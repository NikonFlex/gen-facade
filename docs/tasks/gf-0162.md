## Описание из трекера

ТЗ требует сравнения с базовыми подходами; из четырёх есть один — правило GenPlan (gf#141). LLM без
дообучения отвечает на вопрос «зачем вообще обучать свою модель», его спросят первым.

Что сделать:
- до кода — какую LLM и через что (ключ в `.env`, модель, цена запроса); готовые промпты и работы
  по генерации раскладки фасада/лейаута LLM без дообучения — найти и записать;
- промпт: условие дома (параметры, стены, проёмы плана, запретные зоны) в текстовом виде → ответ
  в нашем формате (токены или JSON листа) → разбор → тот же лист; неразобранный ответ — `{"error": …}`;
- `genfacade baseline llm <папка листов> -o <папка>` на тех же домах, что модель, затем
  `genfacade metrics` — строка таблицы в обоих режимах;
- платные запросы: сначала сказать хозяину, сколько их будет и почём, прогнать на 1–2 домах; тесты —
  на заглушке, без сети.

`openspec/specs/evaluation/spec.md` — «Базовые подходы»

**Готово, когда:**
- строки «LLM без дообучения» в обоих режимах — в таблице `genfacade metrics` против того же эталона,
  что модель (число домов — по согласованию с хозяином из-за цены), в `docs/metrics-results.md` и в
  низу задачи;
- тест разбора ответа LLM на заглушке, красный на сломанном разборе.

Датчик: доля разобранных ответов LLM на первых 10 домах.

## Чем возобновлять

Ждём решения хозяина по модели и «да» на пробный платный прогон. Проба — 2 дома × 2 режима на
claude-sonnet-5-5, около $0,08. Дальше: код `genfacade baseline llm` с заглушкой вызова в тестах,
пул few-shot из пересобранной синтетики, проба, полный прогон.

## Что осталось

- Решение агента (объявлено хозяину 02.11):
  - модель — claude-sonnet-5-5, расширенное мышление выключено, temperature 0,7, как у
    LayoutGPT и LayoutPrompter;
  - условие и ответ — нашей записью токенов (`tokens.condition` → ответ → `tokens.decode`):
    ответ в 4–5 раз короче JSON, а разбор и страж-валидатор — те же, что у модели;
  - few-shot k = 8 из синтетики: ближайшие по числу сторон, этажей и длинам стен, тот же режим;
  - 27 домов реального теста в примеры не идут — утечка;
  - повтор до 5 попыток, при повторе в промпт идёт текст ошибки.
- Хозяин 02.11: по возможности — на токенах подписки, а не через платный API; **все входы и
  выходы записываются**.
  - Как вызывать: `claude -p` (Claude Code без окна) с `--model claude-sonnet-5-5`,
    `--tools ""` (без инструментов: модель не прочтёт репозиторий и не подсмотрит ответ),
    `--system-prompt` — свой (общий промпт Claude Code заменяется), `--strict-mcp-config`,
    `--no-session-persistence`, `--output-format json`; запуск — из пустой папки, без CLAUDE.md.
  - На этой машине CLI не залогинен (02.11, ответ «Not logged in · Please run /login»): нужен
    вход хозяина `claude /login` подпиской или запуск на его машине.
  - Отличия от API: temperature не задаётся (берётся умолчание модели), действуют лимиты подписки;
    записывается, какая модель ответила (`modelUsage` ответа CLI) и версия CLI.
  - Запись: на каждый запрос — JSON в `outputs/gf162/<запуск>/<дом>-<режим>-<попытка>.json`:
    дата, модель, версия CLI, системный промпт, полный промпт, id примеров few-shot, сырой
    ответ, разбор (`{"error": …}` или лист), usage и стоимость из ответа CLI. Рядом — лист и его
    `.json` (правило `docs/agents/code.md`, «Результаты генерации»). Тесты вызов не делают —
    заглушка.
- Локальные `data/samples/*` собраны до gf#212 и не записываются нынешними токенами. Перед пулом
  few-shot синтетику надо пересобрать.
