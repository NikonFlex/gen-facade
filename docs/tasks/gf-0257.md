## Описание из трекера

Модель gf#250 на реальном тесте ближе к настоящим домам, чем правило GenPlan (c2st 0,716 против
0,896 в «окнах из плана», 0,809 против 0,986 в глухом; GPU run 41360653518), но число — одно, на
одном seed. Без разброса нельзя сказать, что разница с правилом GenPlan не случайна. И один дом не
собирается: ffh-barnhouse в «окнах из плана» — «последовательность оборвалась» во всех 5 попытках.

Что сделать:
- разобрать отказ ffh-barnhouse: длина условия и ответа против `block` модели (1536), где обрывается
  ответ; починить так, чтобы дом собирался, не ломая остальные;
- реальный тест на GPU с 3–5 сидами модели в обоих режимах: среднее и разброс c2st, FID,
  house_density, house_marginal, окон на стену; у правила GenPlan — тоже по сидам, где у него есть
  случайность;
- перебор сэмплинга без обучения: temperature (2–3 значения), top_k, N в «лучшем из N»; что
  меняется в c2st и окнах на стену;
- числа — в `docs/metrics-results.md`, выбор настроек — `docs/decisions.md`.

Готово, когда:
- ffh-barnhouse годен в «окнах из плана» на GPU-прогоне, остальные 26 домов — тоже годны;
- в `docs/metrics-results.md` — таблица «среднее ± разброс по сидам» для модели и правила GenPlan в
  обоих режимах, с номером GPU-прогона;
- там же — таблица перебора temperature / top_k / best_of и выбранные умолчания в
  `genfacade/config/models.toml` с причиной в `docs/decisions.md`.

Датчик: длина условия и ответа в токенах по домам реального теста против `block`; c2st и окон на
стену по сидам.
