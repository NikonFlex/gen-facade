## Описание из трекера

Хозяин 09.11 посмотрел дома новой модели и сказал: «давай задачу заведем, да, надо это починить». У модели после переобучения 08.11 (GPU run 42506371639, gf#318, gf#319, gf#321) три элемента ставятся с другой частотой, чем у настоящих домов [проверено: подсчёт по листам артефакта `realtest-42506371639`, низ `docs/tasks/gf-0318.md` и `gf-0321.md`]:
- окно во фронтоне — у 62 % («окна из плана») и 70 % (глухой) скатных домов модели против 27 % у настоящих (8 из 30);
- ставен на окно — 0,21 у модели против 0,82 у настоящих;
- окно по скату — 36 и 31 у модели против 3 у настоящих.

Скорее всего, дело в долях синтетики, на которой учится модель: генератор (`config/synthetic.toml`) ставит эти элементы чаще или реже, чем бывает на самом деле. Требования «Окно во фронтоне», «Выводимые элементы — по признаку проёма», «Вид выводимых элементов — один на дом» остаются 🚚 до этой задачи (хозяин 09.11).

Что сделать:
- датчик до: доли этих трёх элементов в синтетике, у модели и у настоящих домов, одной командой, в оба режима;
- найти, откуда расхождение: доли генератора, условие модели (`<gable>`, вид ставен дома), сэмплинг;
- поправить доли синтетики (или условие) под настоящие дома — числа с источником в конфиге;
- переобучить на GPU по слову хозяина «обучай» и снять датчик после.

Готово, когда: у новой модели доли окна во фронтоне, ставен на окно и окна по скату — в пределах разброса настоящих домов (интервал — по датчику), реальный тест не хуже прошлого (c2st, FID, rules), хозяин посмотрел дома новой модели в смотрелке.

Датчик: три доли (фронтон, ставни на окно, окна по скату) — синтетика / модель / настоящие дома, по режимам.

Требования: `openspec/specs/facade/spec.md` — «Окно во фронтоне», «Выводимые элементы — по признаку проёма», «Вид выводимых элементов — один на дом».
