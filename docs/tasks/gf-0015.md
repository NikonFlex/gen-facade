## Описание из трекера

Требование ТЗ. Принимает SVG, выдаёт список нарушений.

Черновой набор правил — в `docs/metrics.md`: парсится ли SVG, замкнутость контуров,
самопересечения, выход за габариты, пересечения проёмов, одинаковость размеров
однотипных элементов, выравнивание по осям, постоянство шага этажей.

Допуски обосновать по измерениям на CMP, а не назначать произвольно.

**Готово, когда:** валидатор работает, прогнан на ground truth из CMP
(он должен проходить проверки), допуски обоснованы измерениями.

После gf#11: валидатор по `specs/evaluation.md`; на каждое правило — тест,

## Что установлено

- Правила проверки: SVG парсится; контуры замкнуты, нет самопересечений;
  элементы внутри габаритов фасада; проёмы не пересекаются между собой;
  элементы одного класса на этаже одного размера (с допуском); выравнивание
  по вертикальным осям; постоянство шага этажей; соответствие числа элементов
  условию генерации.
- **Вложенность в данных осмысленная и её надо проверять, а не запрещать:**
  `blind` внутри `window` (777 пар), `deco` в `molding` (746),
  `molding`+`pillar` (549), `balcony`+`window` (192). Пересечение этих пар —
  норма, а не нарушение.
