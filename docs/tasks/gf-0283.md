## Описание из трекера

Хозяин 04.11 (инструкция `task-closing-kit.md`, приложена в чат): PR вливается через минуты после
быстрых проверок, задача закрывается при мерже по строке `Closes #N` в теле PR, полный набор тестов
идёт уже на `main`, красный набор переоткрывает задачи влитых PR с перечнем упавших тестов.

Сейчас всё наоборот: слова закрытия рядом с номером запрещены (`tools/closing_words.py`, сторож
`.agents/guards/guard.py`, хук `commit-msg`), задачу закрывает хозяин после проверки, PR
ссылается «Implements gf#N», мерж — merge-commit, на PR идёт весь `tools/check.sh`.

Что сделать:
- правила: `AGENTS.md`, `docs/agents/tasks.md`, `docs/WHY.md` — `Closes #N` (PR доделывает
  задачу) и `Part of #N` (промежуточный или ждёт проверки хозяином); другие слова закрытия — отказ;
- `tools/pr_link.py` — одно объявление ссылки для CI, сторожа и прогона после мержа; сторож и
  `closing_words.py`, `commit_check.py`, `fpsr.py` — на новые строки;
- CI: `fast` (быстрые проверки) и `pr-link` на PR — обязательные; `post-merge.yml` — полный набор
  на `main`, повтор упавших, `tools/post_merge.py verdict` — переоткрытие и комментарии;
- настройки репозитория: только squash, сообщение — заголовок и тело PR, автомерж, удаление
  веток; защита `main` — `fast`, `pr-link`;
- задача, чей последний критерий — проверка хозяином, получает `Part of`, пока он не посмотрел;
- выкладки у диплома нет — `deploy.yml` не делаем.

Требования: без сценария — процесс разработки, поведение модуля не меняется.

Готово, когда:
- `python3 tools/pr_link.py --selftest` — все случаи; сторож отбивает `gh pr create` с `Fixes #N`;
- защита `main`: `strict: false`, контексты `fast`, `pr-link`;
- PR с `Closes #N` и зелёным `fast` влит без участия человека, задача закрыта, на `main` стартовал
  `post-merge`;
- PR, ломающий тест из полного набора, — после `post-merge` задача переоткрыта, в комментарии тест и
  ссылка на прогон; починка — снова закрыта, комментарий «зелёный».

Датчик: время от создания PR до мержа, до и после.
