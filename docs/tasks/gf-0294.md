## Описание из трекера

Модель шага 4 при ошибке декодирования одной стены (`TokenError` в `train/tokens.py` `decode`)
бракует ответ дома целиком: `pipeline._attempt` возвращает `None, []`, и `wall_retry` не
срабатывает — `pipeline._bad_wall` ищет стену только по нарушениям валидатора (gf#213). Стены,
которые разобрались, генерируются заново. Нашла повторная гигиена чистого контура (gf#293,
карточка C10 «всё или ничего»); там не чинили — это изменение метода.

Что сделать:
- `TokenError` декодирования несёт номер стены, на которой ответ не разобрался (стены в ответе
  разделены метками `<wall>`, `models/layout.py` `redo` их уже находит);
- `pipeline._good` досэмплирует эту стену так же, как стену с ошибкой валидатора; ответ, в котором
  стену не определить (обрыв до первой метки), — брак целиком, как сейчас;
- трасса попытки (`meta.json`, «layout») называет стену и причину.

`openspec/specs/generation/spec.md` — «Брак — заново»

Готово, когда:
- тест на маленькой модели (`tests/tiny_model.py`): ответ, в котором одна стена не
  декодируется, досэмплирует только её — красный на старом коде;
- датчик снят до и после на одном наборе домов и seed: попыток на годный ответ и доля брака по
  декодированию; на GPU — только по «обучай» хозяина.

Датчик: попыток на годный ответ и доля ответов, забракованных декодированием, до → после.

## Что осталось

- Причина попытки в трассе — текст `error` («ответ не разобран: …»), а не код из списка (C6/C15 вне диффа: `BLOCKED_REASON` и тексты `TokenError` — строки с gf#257). Заводить `StrEnum` причины брака — отдельная работа; решает хозяин.
- Брак «страж запретил все токены» (`BLOCKED_REASON`) остаётся браком целиком: номера стены у него нет (в `sampling.BLOCKED` слов нет). Можно вывести стену по числу `<wall>` до метки — не делал.
- Не знаем, как часто такой брак на GPU: замера на GPU нет («только по "обучай"» хозяина) — на GPU естественная доля может быть выше 0 (gf#257) и выигрыш — заметнее, чем на инъекции.

## Что установлено

- `TokenError` теперь несёт `wall` — номер стены в порядке `walls.facades` (`genfacade/train/tokens.py`); `decode` ставит его по тому, на какой стене упал разбор. Не определить — `None`: ошибка в типоразмерах/до первой `<wall>`, лишнее после `<end>`, страж запретил все токены (`BLOCKED_REASON`, слов нет). Хвост мусора вместо `<wall>` следующей стены относится к предыдущей, вместо `<end>` — к последней [проверено: тест `test_undecodable_wall_is_named_and_redone_alone`, обе стены (первая и последняя)].
- `Layout.redo` принимает и `TokenError` вместо `Answer` (нужны только слова) и терпит оборванный ответ без `<end>` (хвоста нет, `<end>` из новой стены сохраняется).
- `pipeline._failed_wall` — одно место решения: `TokenError.wall`, иначе `_bad_wall` по нарушениям; решение не по тексту ошибки (карточка C6). В трассе попытки — поле `bad_wall` (стена) рядом с прежним `error` (причина) и `words`.
- Работает только при `wall_retry = true` (в `config/models.toml` по умолчанию `false`, gf#213); значение по умолчанию не менял.

- **Тест на маленькой модели был нестабилен сам по себе** [проверено: два прогона `test_sampling.py -k redo`, 07.11.2026]: веса `tiny_model.save` случайны, и `model.answer(seed 0)` иногда не разбирался («последовательность оборвалась») — падал и старый `test_redo_changes_only_its_wall`. Фикстура `checkpoint` теперь задаёт `torch.manual_seed(0)` перед сохранением.
- Датчик на CPU при нагрузке машины (load average 10–17 от других агентов): один ответ модели — 5–8 минут, поэтому набор мал (см. «Проверено локально»).
