## Описание из трекера

Препроцессор плана по `specs/plan-input.md`: SVG GenPlan → внутренний `Plan` и стороны дома.
- разбор SVG по цветам (стены, окна, двери), слияние перекрывающихся стен, наружный контур;
- стороны, проекция проёмов на стороны, запретные зоны (примыкание внутренних стен), перевод в метры;
- режим 1 (глухой куб): заделать наружные разрывы, кроме входа; режим 2: проёмы из плана;
- дефектный план — отказ с причиной.

**Готово, когда:** выполнены критерии приёмки `specs/plan-input.md` (пример GenPlan, коробка без ложных проёмов, глухой режим, план без входа), есть тесты.

## Что установлено

- **Препроцессор** `genfacade/plan/`: `genplan_svg` (разбор) → `gaps` (разрывы) → `outline`
  (контур, shapely) → `preprocess` (проёмы, вход, масштаб, глухой режим) → `sides` (стороны,
  проекция, запретные зоны). Все критерии приёмки plan-input.md — `tests/acceptance/test_plan_input.py`;
  15 поломок по одной — каждую ловит тест.
- **На примере** `[проверено: запуск + картинка глазами]`: контур 5.47 × 4.23 м, 4 стороны,
  вход на левой стороне x = 0.52 м шириной 0.9 м, окна на своих местах в пределах 2 px.
  Запретная зона на верхней стороне (1.38–1.45 м) лежит **внутри** окна 0.92–3.08 м — это и есть
  дефект GenPlan, о котором писала Валерия: внутренняя стена x = 714 заходит в полосу окна на
  13 из 17 px. Что с ним делать в режиме 2 — «Открыто» в спеке; пока окно остаётся, зона тоже.
- **`test1`, `test2` GenPlan** (только стены): контуры 6.35 × 4.5 и 4.29 × 2.41 м, вход —
  единственный наружный разрыв; масштаб по входу даёт маленькие дома (вход 50 и 110 px) —
  так же посчитал бы GenPlan.
- **Масштаб по коду GenPlan** `[проверено: three_dimensional/convertor.py:31-32, 249-254]`:
  м/px = 0.9 / ширина входа; высота стены из текста (`WallSizeType` 250/275/300) масштаб не
  задаёт. Правило 2 спеки поправлено.
- **Правило GenPlan на пустой коробке** `[проверено: запуск find_openings, 30.09]`: два ложных
  проёма во весь дом (115,100)–(485,500) и (100,115)–(500,485), оба «наружные». У нас — ни одного.
- **Внутренние стены прорисованы насквозь** до наружной грани (пример: y = 525, x = 440, x = 559):
  признак «касается контура» принял бы их за наружные. Наружная — вытянутая вдоль стороны.
- **Ступеньки контура:** два бага нашлись тестом — допуск в пиксель при проверке «точка на прямой»
  и «повтор точки» срезал ступеньку по диагонали. Контур из прямоугольников строго ортогональный,
  прямая и повтор теперь точные, ступеньки убирает только `_collapse`.
- Рефакторинг `render/svg.py` (общие `canvas`, `add_line`): лист трёх тестовых домов совпал
  с main байт в байт, кроме новых правил CSS для плана.

- **Формат дверей по коду GenPlan** `[проверено: decorator/decoration.py, dto/opened_door/opened_door.py,
  HEAD 2ed651c; запуском]`: в 2D SVG все двери (вход и внутренние) — пустой разрыв, чёрная
  створка 5 px (`DOOR_WIDTH`) длиной в ширину разрыва и дуга-четверть из петли на грани стены.
  Коричневый `[150,80,50]` — только 3D. Створка ставится с меньшей координаты (положения
  RIGHT/BOTTOM), если помещается и не пересекает стен, иначе LEFT/UP; у UP нет `fill`.
  Значит, у входа на верхней и левой стене створка снаружи, на нижней и правой — внутри.
- **Правило разбора двери:** петля — угол дуги (p.x, q.y) или (q.x, p.y), лежащий в
  створке; конец створки — точка дуги в створке; другая точка дуги — край разрыва.
  Работает во всех четырёх положениях — проверено на SVG, нарисованных кодом GenPlan
  (`tests/fixtures/genplan/make_fixtures.py`).
- Decorator GenPlan воспроизводит `test3.svg` поэлементно из его 12 стен — формат понят верно.
  На `test1`/`test2` он падает — записано в gf#36.
- `test1`, `test2` из репо GenPlan — только стены (26 и 92 `<rect>`), холст 683 × 384;
  наш разбор читает их без ошибок.
- XML чужого файла: стандартный парсер без defusedxml — при expat ≥ 2.6.0 он не подвержен
  billion laughs, quadratic blowup и большим токенам, внешних сущностей `xml.etree` не
  раскрывает `[проверено: docs.python.org/3.12/library/xml.html, 30.09]`; здесь expat 2.6.1.
  На старом expat разбор отказывает. `defusedxml` 0.7.1 — релиз 2021-03 `[проверено: PyPI]`.

- **Библиотеки** (30.09, decisions.md): SVG — стандартный `xml.etree`, геометрия —
  `shapely` 2.1.2 `[проверено: PyPI JSON API, 30.09 — BSD-3, релиз 2025-09-24]`;
  `svgelements` 1.9.6 (MIT, релиз 2023-08-17) не нужен: трансформаций в SVG GenPlan нет.
- **Готового разбора нет** (поиск 30.09, запросы «python floor plan wall rectangles exterior
  outline openings detection shapely github», «floor plan vector walls to room polygons exterior
  boundary library python»): FloorPlanNet и FloorPlanParser распознают растр, FloorPlanner —
  редактор на PyQt6; «осевые прямоугольники → контур и проёмы» никто не отдаёт
  `[не проверено: по описаниям в выдаче, код не открывали]`.
- **Пример `materials/genplan-plan-example.svg`** `[проверено: прочитан файл, 30.09]`:
  13 чёрных `<rect>`, 2 окна `#99ccff`, 1 `<path>` дуги. Окна — прямоугольники в разрыве
  стены. Вход нарисован открытым: створка — чёрный `rect` (x 69–187, y 368–373) вне
  контура, дуга от (187, 486) к (69, 368); разрыв входа на левой стене — y 368–486,
  118 px. Коричневой двери в примере нет. Внутренние стены упираются в наружные:
  x = 714 и y = 300 (верх), x = 440 и x = 559 (низ), y = 525 (лево) — будущие запретные зоны.
- По ширине входа 0.9 м масштаб ≈ 0.0076 м/px, дом ≈ 5.5 × 4.2 м — маленький; ориентир для
  проверки, не требование.
- `Plan` хранит метры и y вверх; `scale_m_per_px` — чтобы вернуться к пикселям SVG
  (критерий «точность 2 px»). Стороны лежат в `Plan.sides`: трасса шага 2 — один JSON.
- Проверки схемы: обход контура по часовой (площадь со знаком < 0), ≥ 3 точки, прямоугольник
  непустой, заделать можно только наружный проём и не вход. Каждая проверка ломалась
  по очереди — тест краснел.
