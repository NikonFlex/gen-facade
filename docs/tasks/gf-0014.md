## Описание из трекера

Препроцессор плана по `specs/plan-input.md`: SVG GenPlan → внутренний `Plan` и стороны дома.
- разбор SVG по цветам (стены, окна, двери), слияние перекрывающихся стен, наружный контур;
- стороны, проекция проёмов на стороны, запретные зоны (примыкание внутренних стен), перевод в метры;
- режим 1 (глухой куб): заделать наружные разрывы, кроме входа; режим 2: проёмы из плана;
- дефектный план — отказ с причиной.

**Готово, когда:** выполнены критерии приёмки `specs/plan-input.md` (пример GenPlan, коробка без ложных проёмов, глухой режим, план без входа), есть тесты.

## Что установлено

- **Библиотеки** (30.09, decisions.md): SVG — стандартный `xml.etree`, геометрия —
  `shapely` 2.1.2 `[проверено: PyPI JSON API, 30.09 — BSD-3, релиз 2025-09-24]`;
  `svgelements` 1.9.6 (MIT, релиз 2023-08-17) не нужен: трансформаций в SVG GenPlan нет.
- **Готового разбора нет** (поиск 30.09, запросы «python floor plan wall rectangles exterior
  outline openings detection shapely github», «floor plan vector walls to room polygons exterior
  boundary library python»): FloorPlanNet и FloorPlanParser распознают растр, FloorPlanner —
  редактор на PyQt6; «осевые прямоугольники → контур и проёмы» никто не отдаёт
  `[не проверено: по описаниям в выдаче, код не открывали]`.
- **Пример `materials/genplan-plan-example.svg`** `[проверено: прочитан файл, 30.09]`:
  13 чёрных `<rect>`, 2 окна `#99ccff`, 1 `<path>` дуги. Окна — прямоугольники в разрыве
  стены. Вход нарисован открытым: створка — чёрный `rect` (x 69–187, y 368–373) вне
  контура, дуга от (187, 486) к (69, 368); разрыв входа на левой стене — y 368–486,
  118 px. Коричневой двери в примере нет. Внутренние стены упираются в наружные:
  x = 714 и y = 300 (верх), x = 440 и x = 559 (низ), y = 525 (лево) — будущие запретные зоны.
- По ширине входа 0.9 м масштаб ≈ 0.0076 м/px, дом ≈ 5.5 × 4.2 м — маленький; ориентир для
  проверки, не требование.
- `Plan` хранит метры и y вверх; `scale_m_per_px` — чтобы вернуться к пикселям SVG
  (критерий «точность 2 px»). Стороны лежат в `Plan.sides`: трасса шага 2 — один JSON.
- Проверки схемы: обход контура по часовой (площадь со знаком < 0), ≥ 3 точки, прямоугольник
  непустой, заделать можно только наружный проём и не вход. Каждая проверка ломалась
  по очереди — тест краснел.

## История: прежняя формулировка задачи (до 29.09, CMP)

Задача была про нормализацию перекошенных кадров CMP; переформулирована 29.09 хозяином.

- «Rectified» в CMP не значит «идеально фронтально»: часть кадров заметно
  скошена, видно на `docs/assets/cmp_annotation_check.png` (правый столбец).
- Разброс размеров окон внутри кадра: медиана 17% по высоте, 23% по ширине.
  Часть этого — перекос, часть — реальное разнообразие (витрины первого этажа,
  мансарды).
- Нормализация кадров CMP и замер регулярности после неё — при надобности отдельной
  задачей (этап 2, gf#12).
