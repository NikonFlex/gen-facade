## Описание из трекера

Хозяин 09.11: нужна метрика, что дом согласован с промптом; готовых метрик для этого, вероятно, нет. Сейчас есть `evaluation: Соответствие описанию` (gf#16): доля выполненных требований текста, проверяет парсер чертежа — но только те поля, что понимает стаб шага 1 (этажи, крыша, материал, стиль, элементы).

Что сделать:
- исследование: метрики соответствия тексту в генерации (CLIPScore, TIFA, VQAScore, DSG, T2I-CompBench и т. п.), в генерации планов и 3D (текст → дом), что подходит векторному чертежу; что искали и не нашли — записать (аргумент новизны);
- своя метрика: разбор текста на проверяемые утверждения (этажи, крыша, материал, цвет, стиль, элементы, их число и место — «окна по бокам от двери», «два окна на втором этаже») → проверка каждого по листу дома (парсер чертежа, не детектор по растру) → доля выполненных; утверждения, которые нельзя проверить по листу, — отдельно;
- набор описаний для проверки: тексты к домам реального теста и синтетики, часть — написаны людьми;
- проверка метрики людьми (gf#389): сходится ли доля выполненных с оценкой «сделано по описанию».

Готово, когда: метрика считается для всех строк таблицы реального теста; на наборе с оценками людей посчитано её согласие с людьми; исследование с источниками — в `docs/metrics.md`.

Датчик: доля утверждений текста, которые метрика умеет проверить по листу.

`openspec/specs/evaluation/spec.md` — «Соответствие описанию»
