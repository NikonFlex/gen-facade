## Facades-3D — самое важное

https://github.com/CTLab-ITMO/Facades-3D · Python · MIT · создан 2026-06-30, обновлён 2026-09-13

**Лаборатория уже генерирует фасады.** Приложение принимает mass-модель здания,
текстовый промпт и опционально референс стиля, а выдаёт 3D-модель жилого здания
с детализированным экстерьером.

Модули в `src/`: `walls_clustering.py`, `gen_wall.py`, **`facade_semantic_map_gen_v2.py`**,
`trellis_image_to_facade.py`, `gen_facades.py`, `server.py`.
Из CLI видно: diffusion + ControlNet (`--controlnet-conditioning-scale`,
`--cross-attention-scale`, `--style-ref-scale`), затем TRELLIS для 3D
(`--slat-steps`, `--mesh-simplify`, `--texture-size`).

### Что это значит для диплома

**Хорошее.** Это ровно та часть, которую Егор обещал сделать сам («натягивать фасады
на домики я сам»). То есть 3D-конец уже существует и работает — наш модуль встаёт перед ним.
И это готовый растровый генератор фасадов для пути B: свою диффузию с нуля поднимать
не нужно, ControlNet и управление стилем уже настроены.

**Тревожное.** Нужно точно понять, чего Facades-3D **не** делает, иначе диплом рискует
оказаться пересказом существующего. Судя по всему, он делает растр и текстуры на меше,
а **векторного чертежа не производит** — вот в этом зазоре и живёт тема. Это надо
подтвердить по коду и проговорить с Егором.

**Ключевой вопрос.** В `facade_semantic_map_gen_v2.py` есть «семантическая карта фасада» —
структурированное промежуточное представление. Возможно, оно близко к тому формальному
представлению, которое требует ТЗ. Если так — брать его, а не изобретать своё.

## Text2SVG — путь A уже частично построен

https://github.com/CTLab-ITMO/Text2SVG · Jupyter/Python · создан 2025-02-13, обновлён 2026-08-27 · ★6

Тулкит для генерации SVG по тексту. Именно это Егор имел в виду, советуя «смотреть на
LLM-модели» — он отправлял к своей же лаборатории.

```
svg-corpus/
  mining/         скрапинг SVG из веба, ~4 млн URL в месяц с дедупликацией
  optimization/   двухстадийная оптимизация SVG
  captioning/     генерация описаний SVG с помощью VLM
llm4svg/          файнтюн LLM под генерацию SVG (run_training.py, run_eval.py)
svg-encoder/      энкодер SVG
```

### Что это значит для диплома

- Путь A («сразу SVG через LLM») — не с нуля: есть пайплайн файнтюна и энкодер SVG.
- **`svg-corpus/captioning` закрывает нашу дыру с отсутствием описаний.** В CMP Facade
  текстовых описаний нет, а по контракту вход — описание. VLM-каптионинг из этого репо
  можно направить на фасады.
- `svg-encoder` — готовый кандидат на представление SVG для модели.

## VGLib — библиотека векторной графики, в ней EvoVec

https://github.com/CTLab-ITMO/VGLib · Python · создан 2024-05-22, обновлён 2025-06-05 · ★6

«Библиотека методов машинного обучения по обработке и генерации векторной графики».
Поддержана НТИ, соглашение 70-2021-00187.

Содержит:

| Метод | Что делает |
|---|---|
| **EvoVec-Evolutionary-Image-Vectorization/** | эволюционная векторизация — **статья Егора** |
| VectorWeaver/ | безусловный генератор векторных изображений, двухстадийный трансформер |
| VectorNST/ | перенос стиля в векторной графике |
| CoverGAN/ | генератор векторных обложек альбомов |
| extended_recursive_memory_transformer/ | детекция плагиата чертежей, рекуррентный трансформер с памятью |

**Вот где лежит EvoVec** — искали отдельный репозиторий, а он подпапкой здесь.
Структура: `main.py`, `vectorize_by_algo.py`, `config.py`, `cache.py`,
`crossover/`, `mutations/`, `fitness/`, `dto/`, `utils/`, `test/`.

Отдельного внимания заслуживает **VectorWeaver** — трансформерный генератор векторной
графики. Для пути A это прямой методологический ориентир внутри своей же лаборатории.

## Прочее в организации, что может пригодиться

- **CoolPrompt** (★197) — фреймворк автоматической оптимизации промптов. Может пригодиться,
  если вход в нашу модель — текстовое описание.
- **diff-aug** — аугментации на основе диффузионных моделей для детекции и сегментации.
  Кандидат на решение проблемы 606 изображений.
- **CTCI / CTCI-generation** — генерация однородных данных, синтетика.

## Выводы

1. **Свою диффузию поднимать не нужно** — Facades-3D уже генерирует растровые фасады
   с ControlNet и управлением стилем.
2. **Свой векторизатор писать не нужно** — EvoVec (VGLib) и LIVBOC готовы.
3. **Проблема отсутствия описаний решаема** — VLM-каптионинг в Text2SVG.
4. **Путь A не с нуля** — llm4svg, svg-encoder, VectorWeaver.
5. **Метрик векторной графики в лаборатории нет** — VecScore пустой. Это дырка,
   которую можно закрыть своим вкладом.

Главный риск теперь другой, чем казался: не «не хватит инструментов», а
**«всё уже сделано до меня, где моя новизна»**. Ответ, судя по всему, в зазоре между
Facades-3D (растр + 3D, без вектора) и EvoVec (вектор, но без понимания структуры фасада).
Подтвердить по коду, прежде чем фиксировать тему.
