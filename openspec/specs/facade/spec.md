# Представление фасада и формат выхода

## Purpose
Тип: сущность. Как фасад устроен внутри модуля и что модуль отдаёт наружу: параметры дома,
общие для всех сторон, фасад стороны из элементов и зон отделки, лист фасадов в SVG и JSON.
Главное свойство — фасады одного дома сходятся на углах по построению. Сторону объявляет спека
`plan-input`, как фасад генерируется — спека `generation`.

## Requirements

### Requirement: Элемент — класс и прямоугольник
Модуль MUST описывать элемент фасада классом и осевым прямоугольником в метрах стены, с этажом
и родителем.

**Источник:** ТЗ 7.3 (стр. 26); решение агента 25.09.2026 — элемент как в разметке CMP: класс и прямоугольник

#### Scenario: Окно с подоконником
- GIVEN окно 1,2 × 1,4 м на первом этаже и подоконник под ним
- WHEN модуль записывает фасад
- THEN у окна класс «окно» и прямоугольник в метрах, у подоконника родитель — это окно

### Requirement: Общие параметры дома
Модуль MUST задавать этажность, высоты, цоколь, карниз, крышу и палитру один раз на дом,
одинаковыми для всех сторон; по сторонам ставятся только элементы и зоны отделки.

**Источник:** решение агента 28.09.2026 — параметры дома общие для всех сторон

#### Scenario: Четыре стороны
- GIVEN дом с параметрами: 1 этаж, карниз 3,25 м
- WHEN модуль строит четыре фасада
- THEN у всех четырёх карниз на 3,25 м

### Requirement: Углы сходятся
Модуль MUST строить фасады так, чтобы на углах дома у соседних фасадов совпадали отметки этажей
и карниза.

**Источник:** решение агента 28.09.2026 — согласованность углов обеспечивают общие параметры дома

#### Scenario: Угол простого дома
- GIVEN лист фасадов простого дома 10 × 5 м
- WHEN сравнивают верх стены у общего угла соседних фасадов
- THEN отметки совпадают

### Requirement: Стена до карниза
Модуль MUST строить стену фасада прямоугольником: длина стороны × высота до карниза.

**Источник:** решение агента 30.09.2026 — развёртка без крыши, стена до карниза

#### Scenario: Сторона 10 м
- GIVEN сторона длиной 10 м и карниз 3,25 м
- WHEN развёртка строит стену
- THEN силуэт стены — прямоугольник 10 × 3,25 м

### Requirement: Плоская крыша
Модуль MUST до этапа модели строить только плоскую крышу, которой на фасаде не видно.

**Источник:** решение агента 01.10.2026 — до модели крыша только плоская

#### Scenario: Лист простого дома
- GIVEN параметры дома с плоской крышей
- WHEN модуль рисует лист
- THEN выше карниза на фасадах ничего нет

### Requirement: Цвет из палитры
Модуль MUST брать материал каждой зоны и элемента из палитры дома, а палитру — из библиотеки
материалов; новых цветов модель не придумывает.

**Источник:** Чат 26–28.09 24 (стр. 178); решение агента 28.09.2026 — «в цвете» — цвет и материал из библиотеки

#### Scenario: Зона цоколя
- GIVEN палитра дома с материалом «цоколь» вида бетон
- WHEN модель ставит зону цоколя
- THEN зона ссылается на материал «цоколь», цвет — его цвет из палитры

### Requirement: Цвет вида по умолчанию
Модуль MUST брать для материала без своего цвета цвет его вида из библиотеки.

**Источник:** решение агента 29.09.2026 — материал без цвета берёт цвет вида

#### Scenario: Штукатурка без цвета
- GIVEN материал вида штукатурка без цвета
- WHEN модуль рисует зону из него
- THEN зона закрашена цветом штукатурки из библиотеки

### Requirement: Состав фасада по уровням
Модуль MUST ставить на стену уровень 1 — проёмы с типом и делением рам, двери, гаражные ворота —
и уровень 2 — зоны отделки, цоколь, подоконники, наличники, ставни, карниз, пояса; из уровня 3 —
козырёк над дверью; крыльцо, балкон, терраса, навес — расширение.

**Источник:** решение агента 28.09.2026 — цель работы — уровни 1–2; решение агента 30.10.2026 — признак у проёма ставит модель, прямоугольник — код

#### Scenario: Стена простого дома
- GIVEN стена простого дома с окном из плана
- WHEN модуль её раскладывает
- THEN на ней окно с делением рамы, подоконник, зоны цоколя и основной отделки

### Requirement: Выводимые элементы — по признаку проёма
Модуль MUST ставить подоконник, наличник и ставни окна и козырёк двери по признаку проёма, а
прямоугольник считать сам по виду элемента из параметров дома: подоконник — под окном, шире на
свес; створка ставни — половина окна, вплотную к раме; козырёк — над дверью, шире на свес.

**Источник:** решение агента 30.10.2026 — признак у проёма ставит модель, прямоугольник — код

#### Scenario: Подоконник по признаку
- GIVEN окно 1,2 × 1,4 м с признаком подоконника, у дома подоконник со свесом 0,05 м
- WHEN модуль ставит выводимые элементы
- THEN под окном подоконник шириной 1,3 м, его верх — на низе окна

#### Scenario: Ставни по признаку
- GIVEN окно шириной 1,2 м с признаком ставен, у дома ставни
- WHEN модуль ставит выводимые элементы
- THEN по бокам окна две створки шириной 0,6 м, высотой окна

### Requirement: Выводимый элемент без места
Модуль MUST NOT ставить подоконник, наличник, ставни или козырёк, который заходит на другой проём,
на его выводимые элементы или на карниз.

**Источник:** решение агента 31.10.2026 — геометрический брак листа

#### Scenario: Козырёк у окна
- GIVEN дверь 2,0–2,9 м с признаком козырька со свесом 0,2 м и окно от 3,0 м на высоте козырька
- WHEN модуль ставит выводимые элементы
- THEN козырька нет, а при окне от 5,0 м он есть

### Requirement: Вид выводимых элементов — один на дом
Модуль MUST задавать вид подоконника, наличника, ставен и козырька один раз на дом, в параметрах
дома; у дома без вида такие элементы не ставятся ни на одной стене.

**Источник:** решение агента 30.10.2026 — признак у проёма ставит модель, прямоугольник — код

#### Scenario: Дом без ставен
- GIVEN параметры дома: ставни — «нет»
- WHEN модуль строит четыре фасада
- THEN ставен нет ни на одной стене

### Requirement: Высоты цоколя и карниза — из параметров
Модуль MUST брать высоты цоколя и карниза из параметров дома; на стене модель решает только,
есть ли зона или элемент и из какого материала палитры.

**Источник:** решение агента 29.09.2026 — высоты цоколя и карниза одни на дом

#### Scenario: Цоколь на двух стенах
- GIVEN параметры дома с цоколем 0,5 м
- WHEN модель ставит зону цоколя на двух стенах
- THEN на обеих она от 0 до 0,5 м

### Requirement: Нуль отметок — земля
Модуль MUST отсчитывать высоты от уровня земли: цоколь — от 0 до высоты цоколя.

**Источник:** решение агента 29.09.2026 — нуль отметок — уровень земли

#### Scenario: Цоколь 0,5 м
- GIVEN цоколь 0,5 м
- WHEN модуль строит зону цоколя
- THEN её низ на отметке 0, верх — на 0,5 м

### Requirement: Виды двери
Модуль MUST различать двери: глухая, со стеклом в полотне, с остеклённой фрамугой над полотном —
фрамуга входит в высоту элемента.

**Источник:** решение агента 01.10.2026 — виды входной двери на простом доме

#### Scenario: Дверь с фрамугой
- GIVEN вход 0,9 × 2,4 м с остеклённой фрамугой
- WHEN модуль записывает элемент
- THEN это одна дверь высотой 2,4 м с вариантом «с фрамугой»

### Requirement: Проёмы плана — условие
Модуль MUST помечать у проёма из плана в режиме «окна из плана» положение и ширину как
заданные условием, а не моделью.

**Источник:** решение агента 29.09.2026 — проёмы плана — маска условия

#### Scenario: Окно из плана
- GIVEN окно плана на стороне: положение 2 м, ширина 1,5 м
- WHEN модуль раскладывает стену в режиме «окна из плана»
- THEN у окна положение и ширина помечены заданными условием

### Requirement: Лист с отметками и осями
Модуль MUST оформлять лист как в эскизном проекте ИЖС: фасады в осях, отметки уровней — ноль,
цоколь, этажи, карниз.

**Источник:** Чат 26–28.09 27 (стр. 196–198)

#### Scenario: Отметки простого дома
- GIVEN дом: цоколь 0,5 м, один этаж, карниз 3,25 м
- WHEN модуль рисует лист
- THEN у фасадов отметки нуля, цоколя и карниза и подписи осей

### Requirement: Элементы в SVG
Модуль MUST писать каждый элемент в SVG прямоугольником или многоугольником с классом и
материалом; координаты — метры в едином масштабе листа.

**Источник:** ТЗ 7.7 (стр. 30); решение агента 28.09.2026 — свой формат SVG с классом и материалом

#### Scenario: Окно в SVG
- GIVEN окно 1,2 × 1,4 м
- WHEN модуль пишет лист
- THEN в SVG прямоугольник с классом «окно» и материалом, размером 1,2 × 1,4 м в масштабе листа

### Requirement: JSON и SVG — одно содержимое
Модуль MUST писать в JSON ровно то же, что в SVG, и получать SVG из JSON детерминированно.

**Источник:** решение агента 28.09.2026 — JSON и SVG — одно содержимое

#### Scenario: Туда и обратно
- GIVEN лист фасадов простого дома в JSON
- WHEN из него рисуют SVG и разбирают SVG обратно
- THEN набор элементов тот же; второй SVG из того же JSON совпадает с первым

### Requirement: CAD через экспорт
Модуль MUST обеспечивать совместимость с CAD экспортом SVG в DXF готовой библиотекой.

**Источник:** ТЗ 7.7 (стр. 30); решение агента 28.09.2026 — DXF готовой библиотекой, своего конвертера нет

#### Scenario: DXF
- GIVEN лист фасадов в SVG
- WHEN его экспортируют в DXF
- THEN файл открывается в CAD без ошибок

### Requirement: Разметка CMP без потерь
Модуль MUST переводить размеченный фасад CMP в фасад стороны и обратно без потерь классов и
координат с точностью квантования.

**Источник:** решение агента 25.09.2026 — элемент как в разметке CMP: класс и прямоугольник

#### Scenario: Фасад CMP
- GIVEN размеченный фасад CMP
- WHEN его переводят в фасад стороны и обратно
- THEN классы те же, координаты отличаются не больше шага квантования 5 см
