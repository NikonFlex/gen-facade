# Метод: от текста и плана к элементам фасада

## Purpose
Тип: процесс. Как по Запросу (`task`) получить Лист фасадов (`facade`): семь шагов конвейера,
модели шагов 1 и 4 и их стабы, запись дома токенами, режимы, привязка к сетке, трасса, кандидаты
архитектуры. Выбор основной архитектуры ещё не сделан; здесь — каркас, общий для всех кандидатов.

## Requirements

### Requirement: Конвейер из семи шагов
Модуль MUST строить фасады за шаги: 1 текст → параметры дома; 2 план → стороны, проёмы,
запретные зоны, метры; 3 развёртка стен; 4 раскладка каждой стены; 5 привязка к сетке и
валидатор; 6 лист фасадов; 7 окна в 3D-конвертер GenPlan — позже. Модель — шаги 1 и 4, остальное
код.

**Источник:** Чат 26–28.09 8 (стр. 93–103); решение агента 28.09.2026 — семь шагов, модель на шагах 1 и 4

#### Scenario: Трасса шагов
- GIVEN запрос на простой дом 10 × 5 м
- WHEN модуль его выполнил
- THEN в трассе выход каждого из шагов 1–6

### Requirement: Оформление только на листе
Модуль MUST класть цвета, отметки уровней и оси только на лист (шаг 6); на шагах 3–5 оформления
нет.

**Источник:** решение агента 30.09.2026 — оформление только на листе

#### Scenario: Развёртка
- GIVEN трасса прогона простого дома
- WHEN смотрят выход шага 3
- THEN на нём силуэты стен без цветов материалов, отметок и осей

### Requirement: Разбор текста — модель шага 1
Модуль MUST получать параметры дома из текста отдельным шагом, который делает модель; параметры
можно задать и без текста — так работает условная генерация по этажности и типам элементов.

**Источник:** ТЗ 7.8 (стр. 31); решение агента 28.09.2026 — разбор текста — отдельный шаг, его делает модель

#### Scenario: Параметры без текста
- GIVEN параметры дома: 2 этажа, плоская крыша — заданы без текста
- WHEN модуль строит фасады
- THEN у фасадов 2 этажа

### Requirement: Стаб шага 1
Модуль MUST до модели отдавать на шаге 1 на любой текст одни и те же параметры дома: один этаж,
плоская крыша, палитра по ролям — основная, цоколь, акцент, обрамление, крыша; текст остаётся в
запросе.

**Источник:** решение агента 30.09.2026 — стаб с интерфейсом модели, а не парсер по словам

#### Scenario: Два разных текста
- GIVEN тексты «A simple one-storey house» и «A two-storey villa»
- WHEN шаг 1 работает на стабе
- THEN параметры дома одинаковы: 1 этаж, плоская крыша

### Requirement: Стаб шага 4
Модуль MUST до модели отдавать на шаге 4 для каждой стены простого дома заготовленные элементы и
зоны, один набор на оба режима, а на плане, которого стаб не знает, — отказ с причиной.

**Источник:** решение агента 30.09.2026 — стаб шага 4 с заготовкой простого дома

#### Scenario: Незнакомый план
- GIVEN план, у которого стороны не совпадают с простым домом 10 × 5 м
- WHEN шаг 4 работает на стабе
- THEN отказ с причиной, лист не строится

### Requirement: Раскладка — последовательность токенов
Модель шага 4 MUST выдавать раскладку стены последовательностью токенов: элементы «класс,
вариант, x, y, w, h» и зоны «роль, материал палитры, многоугольник»; числа — целые шаги сетки
5 см.

**Источник:** решение агента 01.10.2026 — запись дома токенами, сетка 5 см

#### Scenario: Окно на сетке
- GIVEN окно с левым краем 2,00 м и шириной 1,50 м
- WHEN его записывают токенами
- THEN левый край — 40 шагов, правый — 70 шагов сетки

### Requirement: Условие модели шага 4
Модуль MUST подавать модели шага 4 условие: режим, параметры дома, палитру и по каждой стене
длину, отметку входа, запретные зоны, проёмы плана.

**Источник:** решение агента 01.10.2026 — запись дома токенами, сетка 5 см

#### Scenario: Стена со входом
- GIVEN сторона входа длиной 10 м с запретной зоной
- WHEN модуль готовит условие
- THEN в условии этой стены — длина, вход и запретная зона

### Requirement: Дом — одна последовательность
Модуль MUST подавать стены одного дома одной последовательностью по обходу контура от стороны
входа: к очередной стене модель видит уже разложенные.

**Источник:** решение агента 01.10.2026 — весь дом одной последовательностью

#### Scenario: Вторая стена
- GIVEN дом из четырёх стен
- WHEN модель раскладывает вторую по обходу стену
- THEN в её входе уже есть раскладка стены входа

### Requirement: Негодный ответ — отказ
Модуль MUST отказывать с причиной на негодной последовательности модели, а не чинить её.

**Источник:** решение агента 01.10.2026 — негодный ответ разбор не чинит

#### Scenario: Обрыв ответа
- GIVEN ответ модели оборван посреди элемента
- WHEN модуль его разбирает
- THEN отказ с причиной, элемент не достроен

### Requirement: Режимы отличаются входом
Модуль MUST различать режимы только входом: в «окна из плана» положения и ширины проёмов заданы,
модель достраивает высоты, зоны и декор; в «глухой куб» модель ставит и проёмы.

**Источник:** Чат 26–28.09 17 (стр. 137); решение агента 29.09.2026 — одно представление, проёмы плана — маска

#### Scenario: Окна из плана
- GIVEN окно плана: положение 2 м, ширина 1,5 м
- WHEN модель раскладывает стену в режиме «окна из плана»
- THEN у окна на фасаде положение 2 м и ширина 1,5 м, высоту ставит модель

### Requirement: Этажность — шаг 1
Модуль MUST брать этажность из параметров дома (шаг 1), а не из ответа модели шага 4.

**Источник:** решение агента 29.09.2026 — этажность задаёт шаг 1

#### Scenario: Двухэтажный дом
- GIVEN параметры дома: 2 этажа
- WHEN модель раскладывает стену
- THEN линии этажей на фасаде — по высотам этажей из параметров

### Requirement: Сначала режим окон из плана
Работа MUST делать модель и метрики сначала для режима «окна из плана», затем для «глухой куб».

**Источник:** Чат 29.09–06.10 8 (стр. 43); решение агента 29.09.2026 — порядок режимов

#### Scenario: Первая модель
- GIVEN план работ по модели
- WHEN выбирают режим первой модели
- THEN это режим «окна из плана»

### Requirement: Проёмы плана на месте
Модуль MUST в режиме «окна из плана» ставить все проёмы плана на фасад в тех же положениях с
допуском шага квантования.

**Источник:** Чат 26–28.09 17 (стр. 137)

#### Scenario: Простой дом
- GIVEN простой дом 10 × 5 м с окнами и входом
- WHEN модуль строит фасады в режиме «окна из плана»
- THEN каждый проём плана стоит на своей стороне в том же положении с точностью 5 см

### Requirement: Окна вне запретных зон
Модуль MUST NOT ставить в режиме «глухой куб» окно в запретную зону.

**Источник:** решение агента 28.09.2026 — окно не ставится у внутренней стены

#### Scenario: Перегородка
- GIVEN сторона с запретной зоной 3,9–4,1 м
- WHEN модель ставит окна в режиме «глухой куб»
- THEN ни одно окно не пересекает 3,9–4,1 м

### Requirement: Стена без проёмов
Модуль MUST принимать стену только с зонами отделки: в «окна из плана» это решает план, в
«глухой куб» — модель по длине стены, запретным зонам, входу и уже разложенным стенам.

**Источник:** решение агента 01.10.2026 — глухая стена — допустимый ответ

#### Scenario: Торец без окон
- GIVEN сторона плана без проёмов в режиме «окна из плана»
- WHEN модуль раскладывает стену
- THEN на ней только зоны отделки, проёмов модель не добавляет

### Requirement: Привязка к сетке
Модуль MUST после генерации выравнивать элементы по линиям этажей и вертикальным осям: соседние
окна получают одинаковые координаты.

**Источник:** решение агента 30.09.2026 — привязка к сетке этажей и осей

#### Scenario: Верх окон этажа
- GIVEN два окна первого этажа с верхом на 2,40 и 2,43 м
- WHEN модуль привязывает фасад к сетке
- THEN верх обоих окон на одной отметке

### Requirement: Брак — заново
Модуль MUST генерировать заново фасад с ошибкой валидатора, когда стоит модель; до модели
нарушения только записываются в трассу.

**Источник:** решение агента 30.09.2026 — до модели без повтора при браке

#### Scenario: Нарушение на стабе
- GIVEN стаб шага 4 дал фасад с нарушением
- WHEN модуль проверяет его валидатором
- THEN нарушение записано в трассу, повтора нет

### Requirement: Детерминизм
Модуль MUST давать на одинаковый вход одинаковый результат: до модели — всегда, с моделью — при
одном seed.

**Источник:** решение агента 30.09.2026 — до модели без seed

#### Scenario: Два прогона
- GIVEN один план и один текст
- WHEN модуль на стабах выполняет запрос дважды
- THEN листы совпадают

### Requirement: Трасса шагов
Модуль MUST сохранять для каждого запуска выход каждого шага 1–6 — JSON и SVG той же отрисовки,
что у листа, — и запись запуска: модель, seed, параметры, дата, версия кода.

**Источник:** решение агента 29.09.2026 — трасса каждого шага для смотрелки

#### Scenario: Прогон
- GIVEN запрос на простой дом
- WHEN модуль его выполнил
- THEN в папке прогона выходы шагов 1–6 и запись запуска

### Requirement: Кандидаты архитектуры
Работа MUST сравнить несколько архитектур, в том числе трансформер и на основе графов:
дообученная LLM, свой компактный трансформер с предобучением на синтетике, диффузия над
множеством элементов с графом отношений.

**Источник:** ТЗ 7.5 (стр. 28); решение агента 28.09.2026 — три кандидата архитектуры

#### Scenario: Таблица сравнения
- GIVEN обученные кандидаты
- WHEN считают метрики на тесте
- THEN в таблице есть строка трансформера и строка графовой модели

### Requirement: Генерация векторного фасада
Работа MUST реализовать генерацию векторного фасада обученной моделью на шаге 4.

**Источник:** ТЗ 7.6 (стр. 29)

#### Scenario: Модель вместо стаба
- GIVEN обученная модель шага 4
- WHEN она стоит вместо стаба
- THEN модуль строит лист фасадов на плане, которого стаб не знает

### Requirement: Растр и EvoVec — базовый подход
Работа MUST использовать путь «растровая генерация → векторизация EvoVec» как базовый подход в
сравнении, а не как основной метод.

**Источник:** ТЗ 12 (стр. 57–58); решение агента 28.09.2026 — растр и EvoVec — базовый подход

#### Scenario: Таблица сравнения
- GIVEN метрики метода и базовых подходов
- WHEN составляют таблицу
- THEN «растр + EvoVec» — строка базового подхода
