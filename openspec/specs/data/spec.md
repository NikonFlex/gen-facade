# Данные

## Purpose
Тип: сущность. На чём модели учатся и на чём проверяются: состав датасета по источникам,
синтетика, тест из реальных данных, описания, хранение примеров. Парных открытых данных «план →
фасады → текст» нет: синтетика даёт пары и объём, реальные данные — проверку и дообучение. План
объявляет спека `plan-input`, лист фасадов — спека `facade`.

## Сущности

### Пример

Один обучающий или тестовый пример.

| Поле | Значение | Источник |
|---|---|---|
| имя | уникально внутри источника; оно же имя файла | решение агента 01.10.2026 — пример — файл по имени |
| план | План (`plan-input`) или нет, если источник без плана (CMP) | решение агента 28.09.2026 — у CMP нет плана |
| эталон | Лист фасадов (`facade`) | решение агента 28.09.2026 — пример — план и все фасады |
| описания | у каждого — вид: шаблонное \| перефразированное \| ручное, и текст | Чат 26–28.09 2 (стр. 28); решение агента 01.10.2026 — вид описания |
| источник | BuildingNet, синтетика, BIO, ручная разметка, CMP, HZNU, LoD3, LSAA | Чат 29.09–06.10 3 (стр. 12–16) |
| часть | обучение \| проверка \| тест | решение агента 29.09.2026 — разбиение по домам |

Состояний нет.

## Связи

| Связь | Кратность |
|---|---|
| Пример — План (`plan-input`) | 1 → 1, необязательно |
| Пример — Лист фасадов (`facade`) | 1 → 1 |

## Requirements

### Requirement: Исследование датасетов
Работа MUST исследовать размеченные датасеты фасадов и описать структуру их объектов.

**Источник:** ТЗ 7.2 (стр. 25)

#### Scenario: Разбор CMP
- GIVEN CMP Facade
- WHEN его разбирают
- THEN описаны классы, формат разметки и распределения размеров элементов

### Requirement: Коттеджи из BuildingNet
Модуль данных MUST собирать примеры коттеджей из BuildingNet: 3D-модели частных домов с
размеченными окнами, дверями, балконами; с них снимаются фасады всех сторон и план.

**Источник:** Чат 29.09–06.10 3 (стр. 13)

#### Scenario: Дом BuildingNet
- GIVEN 3D-модель дома BuildingNet
- WHEN её извлекают
- THEN получен пример: план и фасады всех сторон с окнами и дверями

### Requirement: Извлечение BuildingNet
Модуль данных MUST извлекать дом BuildingNet так: вырезать главный дом, повернуть по осям
контура, взять масштаб по дверям, стороны — в фасады, контур — в план, материалы — в зоны,
брак отфильтровать.

**Источник:** решение агента 29.09.2026 — пайплайн извлечения BuildingNet

#### Scenario: Масштаб по двери
- GIVEN модель в единичном кубе, дверь высотой 0,1 единицы
- WHEN модуль восстанавливает метры по двери высотой 2,1 м
- THEN масштаб — 21 м на единицу

### Requirement: BuildingNet только некоммерчески
Работа MUST NOT распространять модели BuildingNet: публикуются отдельные примеры и код
извлечения.

**Источник:** Чат 29.09–06.10 3 (стр. 13); Чат 29.09–06.10 6 (стр. 31)

#### Scenario: Публикация
- GIVEN готовые примеры из BuildingNet
- WHEN выкладывают материалы работы
- THEN выложен код извлечения и отдельные примеры, но не модели

### Requirement: Синтетика своим генератором
Модуль данных MUST делать синтетику своим генератором: случайный план в формате GenPlan →
препроцессор → параметры дома и раскладка стен правилами → пары «план + все фасады»; синтетика
идёт на предобучение.

**Источник:** Чат 29.09–06.10 3 (стр. 14); решение агента 01.10.2026 — свой генератор на Python вместо Blender

#### Scenario: Один seed
- GIVEN seed 7
- WHEN генератор строит дом
- THEN пример содержит план в формате GenPlan и фасады всех его сторон

### Requirement: Составные крыши в синтетике
Генератор MUST давать скатному дому с крыльями пристройку ниже главного на этаж под односкатной крышей низом от главного, крыльям одной высоты — крышу дома, а двускатному дому щипец над карнизной стеной со входом — с долями, как у настоящих домов теста; словарь условия модели шага 4 от этого не меняется.

**Источник:** решение агента 11.11.2026 — синтетика с составными крышами (gf#431); решение агента 12.11.2026 — пристройка ниже главного (gf#455)

#### Scenario: 300 домов синтетики
- GIVEN 300 синтетических домов, у настоящих домов теста своя крыша части — у 7 из 13 скатных домов с крыльями (0,54, интервал 0,27–0,80), все 9 односкатных пристроек ниже главного, щипец над стеной — у 5 из 32 двускатных
- WHEN генератор строит дома
- THEN своя односкатная — у 48 из 124 крыльев, все ниже главного по карнизу; своя крыша части — у 43 из 110 скатных домов с крыльями (0,39, внутри интервала настоящих; выше не дают дома в один этаж и крылья не меньше 0,6 главного); щипец над входом — у 0,16 двускатных; словарь условия модели шага 4 — тот же; дома с пристройкой ниже главного — образцы, листы и 3D, в корпус обучения модели шага 4 не входят (условие модели ступени не передаёт)

### Requirement: Глухие стены в синтетике
Генератор MUST делать глухие стены намеренно — торцы, стены с гаражом — и записывать их долю в
опись.

**Источник:** решение агента 01.10.2026 — глухая стена — допустимый ответ

#### Scenario: Опись сборки
- GIVEN собранная пачка синтетики
- WHEN открывают её опись
- THEN в ней доля стен без проёмов

### Requirement: Этажность синтетики
Генератор MUST делать дома в 1–3 этажа в долях, заданных настройкой; окна верхних этажей ставит
правило — по осям окон нижнего этажа или своим рядом между запретными зонами; глухая стена глухая
на всех этажах.

**Источник:** решение агента 21.10.2026 — доли этажей по 30 коттеджам BuildingNet: 9, 17, 4

#### Scenario: Пачка синтетики
- GIVEN 400 домов по seed подряд
- WHEN считают этажи
- THEN есть дома в 1, 2 и 3 этажа, и у многоэтажного дома окна стоят на каждом этаже

### Requirement: Сборка синтетики по seed
Модуль данных MUST собирать синтетику по seed подряд: часть зависит только от seed, прерванная
сборка продолжается с готовых домов, дом с ошибкой валидатора не пишется и перечислен в описи.

**Источник:** решение агента 01.10.2026 — сборка синтетики продолжается и не смешивает настройки

#### Scenario: Продолжение
- GIVEN сборка 100 домов прервана на 60-м
- WHEN её запускают снова с теми же настройками
- THEN строятся дома 61–100, первые 60 не пересобираются

### Requirement: Сборка не смешивает настройки
Модуль данных MUST записывать рядом со сборкой настройки генератора и коммит и не продолжать в
ту же папку с другими настройками или кодом.

**Источник:** решение агента 01.10.2026 — сборка синтетики продолжается и не смешивает настройки

#### Scenario: Другие настройки
- GIVEN папка сборки с настройками A
- WHEN сборку продолжают с настройками B
- THEN отказ с причиной

### Requirement: Тест — только реальные данные
Работа MUST строить тест только из ручной разметки реальных чертежей и рендеров; синтетика в
тест не входит, BuildingNet — отдельный второй тест по его части test.

**Источник:** Чат 29.09–06.10 3 (стр. 15); решение агента 29.09.2026 — тест только из реальных данных

#### Scenario: Состав теста
- GIVEN готовый тестовый набор
- WHEN проверяют источники его примеров
- THEN в нём нет синтетики, BuildingNet — в отдельной колонке

### Requirement: Реальные коттеджи — тест
Модуль данных MUST размечать вручную фасады реальных коттеджей с планами — FreeFarmhouse, Solar
Decathlon, российские проекты ИЖС — и рендеры Егора; это тест и дообучение.

**Источник:** Чат 26–28.09 9 (стр. 107); Чат 29.09–06.10 3 (стр. 15); решение агента 07.11.2026 — российские дома со строим.дом.рф

#### Scenario: Дом Solar Decathlon
- GIVEN листы плана и фасадов дома Solar Decathlon
- WHEN его размечают вручную
- THEN получен пример с планом и всеми фасадами, часть — тест

### Requirement: Основа реальных данных — строим.дом.рф
Модуль данных MUST брать реальные дома для теста и дообучения прежде всего с чертежей строим.дом.рф:
план и четыре фасада проекта; план режима «окна из плана» — с чертежа, глухого — тот же план без
проёмов.

**Источник:** решение агента 07.11.2026 — опора на чертежи строим.дом.рф, план GenPlan — позже (gf#342)

#### Scenario: Проект в обоих режимах
- GIVEN проект строим.дом.рф с планом и четырьмя фасадами
- WHEN его размечают
- THEN получен пример в обоих режимах: план с проёмами чертежа и тот же план без проёмов

### Requirement: Проверка разметки домов в браузере
Модуль данных MUST давать проверить разметку дома строим.дом.рф в браузере: рамки и линии этажей поверх листов фасадов правятся мышью и пальцем; дом решается «хорошо», «поправлен» или «негоден» с причиной из списка, правка пишется в разметку дома.

**Источник:** решение агента 08.11.2026 — проверка автоматической разметки за 2 минуты на дом (gf#348)

#### Scenario: Окно сдвинуто мышью
- GIVEN дом из очереди с окном на южной стороне и открытая страница дома
- WHEN хозяин сдвигает рамку окна на 1,5 м вправо и жмёт «Сохранить правку»
- THEN дом получает состояние «поправлен», разметка дома содержит рамку на новом месте, а собранный пример — окно на 1,5 м правее

#### Scenario: Дом негоден
- GIVEN открытый дом со счётом «проверено 0, осталось 11»
- WHEN хозяин жмёт «Негоден» и выбирает причину «масштаб не определить»
- THEN дом получает состояние «негоден» с этой причиной, счёт — «проверено 1, осталось 10», время на дом записано в файл очереди

### Requirement: Правка крыши в браузере
Модуль данных MUST давать на странице проверки разметки править полями вид, уклон и свесы крыши, вид кровли, водосток и виды обрамления дома, а отметками на виде — трубы, мансардные окна, слуховые окна и крыльцо под кровлей; правка пишется в разметку дома.

**Источник:** решение агента 13.11.2026 — разметка строим.дом.рф целиком за один проход (gf#470)

#### Scenario: Уклон и труба
- GIVEN открытый дом с вальмовой крышей 22° без трубы
- WHEN хозяин ставит уклон 30°, отмечает трубу на виде южной стены и жмёт «Сохранить правку»
- THEN дом получает состояние «поправлен», в разметке уклон 30° и одна труба на этом месте

### Requirement: Лист и 3D дома при проверке разметки
Страница проверки разметки MUST показывать лист фасадов и 3D-дом, которые модуль собирает из разметки дома с несохранёнными правками, и пересобирать их после каждой правки; дом, который не собирается, — текст отказа сборщика вместо листа и 3D.

**Источник:** решение агента 14.11.2026 — лист и 3D на странице проверки (gf#470)

#### Scenario: Труба появилась на листе и в 3D
- GIVEN открытый дом с вальмовой крышей 22° без трубы, лист модуля и 3D на странице
- WHEN хозяин отмечает трубу на виде южной стены и отпускает мышь
- THEN лист и 3D пересобираются из разметки с несохранённой правкой: на южном фасаде и на крыше одна труба, файл разметки не менялся

#### Scenario: Дом не собирается
- GIVEN открытый дом, у которого после правки вид кровли не из каталога
- WHEN страница просит лист и 3D
- THEN вместо листа и 3D — текст отказа с кодом правки, не складывающейся в разметку

### Requirement: Многоквартирные из открытых датасетов
Модуль данных MUST собирать многоквартирные из CMP, HZNU и LoD3: раскладка одной стены без плана.

**Источник:** Чат 29.09–06.10 3 (стр. 16)

#### Scenario: Фасад CMP
- GIVEN фасад CMP
- WHEN его переводят в пример
- THEN у примера нет плана, фасад один

### Requirement: CMP без плана
Модуль данных MUST моделировать у CMP режим «окна из плана» по разметке: горизонтали окон берутся
как заданные; тег x разметки CMP — вертикальная ось.

**Источник:** решение агента 28.09.2026 — у CMP нет плана, режим по разметке

#### Scenario: Окно CMP
- GIVEN окно CMP с тегом x от 0,2 до 0,4
- WHEN модуль переводит разметку
- THEN это вертикальный интервал окна, его горизонталь — заданное условие

### Requirement: Данные лаборатории
Работа MUST считать данными лаборатории присланные рендеры коттеджей без разметки: городского
датасета растров от векторных фасадов нет.

**Источник:** ТЗ 4 (стр. 16); Чат 26–28.09 22 (стр. 156–170); решение агента 29.09.2026 — городского датасета у лаборатории нет

#### Scenario: Рендеры Егора
- GIVEN папки, присланные Егором 28.09
- WHEN их разбирают
- THEN это 306 растровых рендеров коттеджей без разметки

### Requirement: Описания из разметки
Модуль данных MUST синтезировать описания из разметки по шаблонам, перефразировать их LLM, а
часть теста писать вручную.

**Источник:** Чат 26–28.09 2 (стр. 28); решение агента 28.09.2026 — ручные описания в тесте против выучивания шаблона

#### Scenario: Эталон и описание
- GIVEN эталонный фасад и шаблонное описание из его разметки
- WHEN парсер описания проверяет эталон
- THEN выполнены 100% требований описания

### Requirement: Без SYNBUILD-3D
Работа MUST NOT брать SYNBUILD-3D: фасады вырождены — окно с подоконником в треть этажа, двери на
верхних этажах.

**Источник:** решение агента 29.09.2026 — SYNBUILD-3D проверен и отброшен

#### Scenario: Выбор источников
- GIVEN список источников данных
- WHEN собирают обучение
- THEN SYNBUILD-3D в нём нет

### Requirement: Стена до карниза в данных
Модуль данных MUST обрезать стену примера по карнизу, кроме окон во фронтоне: окно щипцовой стены,
целиком стоящее в стене с фронтоном, какой её строит модуль по крыше дома, остаётся окном этажа
под скатом вместе со своими подоконником и ставнями; остальное выше карниза отбрасывается.
Исходный вид крыши, число срезанных элементов и число окон во фронтоне — в описи источника.

**Источник:** решение агента 01.10.2026 — в данных стена до карниза; решение агента 08.11.2026 — окна во фронтоне (gf#321)

#### Scenario: Дом со скатной крышей
- GIVEN дом с двускатной крышей, окном во фронтоне торца и окном поперечного щипца над карнизной стеной
- WHEN его переводят в пример
- THEN окно во фронтоне торца в примере — окно этажа под скатом, окна поперечного щипца нет; в описи — 1 окно во фронтоне и 1 срезанный элемент

#### Scenario: Окно по скату
- GIVEN окно вида «по скату», рамка которого выходит за скат щипца
- WHEN внутри стены остаётся не меньше половины рамки
- THEN в примере оно — окно этажа под скатом; иначе его срезает карниз

### Requirement: Разметка — запись чертежа целиком
Модуль данных MUST размечать фасад реального дома целиком — силуэт стены, участки карниза, крышу и элементы выше карниза — и брать в пример то, что модуль держит: дом, чьи участки карниза ложатся на части (одна этажность и отметка на часть, `Крылья по ступени карниза`); иначе строка описи «ждёт».

**Источник:** решение агента 06.11.2026 — разметка целиком, тест растёт вместе с модулем; решение агента 08.11.2026 — дом из частей разной высоты (gf#322); решение агента 10.11.2026 — ступени (gf#422)

#### Scenario: Дом с одноэтажной пристройкой
- GIVEN Г-образный дом: главное крыло с карнизом 4,0 м и нижнее крыло с карнизом 3,5 м, в один этаж оба
- WHEN его размечают и собирают тест
- THEN пример есть, у нижнего крыла отметка карниза 3,5 м, у главного 4,0 м

#### Scenario: Фронтон над карнизной стеной
- GIVEN разметка, у которой на силуэте карнизной стены внутри неё треугольник над карнизом от 7' до 13' с вершиной на 3' над карнизом
- WHEN его размечают и собирают тест
- THEN у примера на этой стене щипец от 2,13 до 3,96 м с уклоном 45°

#### Scenario: Фронтон у угла стены
- GIVEN разметка дома без крыльев: на силуэте карнизной стены 9,75 м треугольник над карнизом от угла стены до 16' с вершиной на 8' над карнизом
- WHEN его размечают и собирают тест
- THEN у примера на этой стене щипец от 0 до 4,88 м с уклоном 45°; у дома из крыльев такой треугольник — фронтон крыла, щипца нет

#### Scenario: Два карниза на одном крыле
- GIVEN дом, у которого на одном крыле контура участки карниза на отметках 3,0 и 4,7 м, а линии ступени на боковых стенах нет
- WHEN его размечают и собирают тест
- THEN примера нет, в описи дом — среди ждущих с причиной «части разной высоты»

#### Scenario: Ступень внутри прямоугольного контура
- GIVEN прямоугольный дом, у которого карниз задних 3 м боковых стен ниже на этаж
- WHEN его размечают и собирают тест
- THEN пример есть: контур режет линия ступени, у листа два крыла со своими этажностью и карнизом

#### Scenario: Крыша дома из разметки
