# Оценка: валидатор, метрики, сравнения

## Purpose
Тип: сущность. Как проверяется, что фасад правильный, и что метод лучше базовых подходов:
валидатор и его нарушения, пять групп метрик ТЗ и две свои, базовые подходы, ablation, тестовые
таблицы. Лист фасадов объявляет спека `facade`, данные теста — спека `data`.

## Requirements

### Requirement: Валидатор
Валидатор MUST принимать лист фасадов или SVG и выдавать список нарушений.

**Источник:** ТЗ 7.9 (стр. 32)

#### Scenario: Эталонный лист
- GIVEN лист фасадов простого дома без дефектов
- WHEN его проверяет валидатор
- THEN ошибок нет

### Requirement: Ошибки геометрии
Валидатор MUST давать ошибку, если SVG не разбирается, элемент выходит за силуэт стены, проёмы
пересекаются, окно, поставленное моделью, стоит в запретной зоне или на углах не совпадают отметки.

**Источник:** Чат 26–28.09 4 (стр. 47); решение агента 30.09.2026 — правила валидатора шага 5; решение агента 17.10.2026 — окно плана в запретной зоне — предупреждение

#### Scenario: Пересечение окон
- GIVEN на стене два окна, перекрывающихся на 0,3 м
- WHEN валидатор проверяет фасад
- THEN ошибка «проёмы пересекаются» с именами обоих окон

### Requirement: Окно плана в запретной зоне
Валидатор MUST предупреждать, а не давать ошибку, если в режиме «окна из плана» в запретной зоне
стоит окно, заданное планом.

**Источник:** Чат 26–28.09 21 (стр. 149); решение агента 17.10.2026 — окно плана в запретной зоне — предупреждение

#### Scenario: Стена в окне плана
- GIVEN окно плана 3,0–5,0 м и запретная зона 3,91–4,0 м поверх него
- WHEN валидатор проверяет фасад в режиме «окна из плана»
- THEN ошибок нет, предупреждение «окно плана в запретной зоне»

### Requirement: Проём плана на месте
Валидатор MUST давать ошибку в режиме «окна из плана», если проём плана на фасаде отсутствует или
смещён.

**Источник:** решение агента 30.09.2026 — правила валидатора шага 5

#### Scenario: Смещённое окно
- GIVEN окно плана на 2,0 м, а на фасаде на 2,5 м
- WHEN валидатор проверяет фасад
- THEN ошибка о проёме плана

### Requirement: Предупреждения выравнивания
Валидатор MUST предупреждать, если верх окон одного этажа не на одной линии или окна почти на
одной оси сверх допуска; низ окон может различаться.

**Источник:** Чат 26–28.09 4 (стр. 48); решение агента 01.10.2026 — выравнивание окон по верху

#### Scenario: Окно в пол
- GIVEN на этаже окно в пол и обычное окно с общим верхом
- WHEN валидатор проверяет фасад
- THEN предупреждений о выравнивании нет

### Requirement: Без норм ГОСТ
Валидатор MUST NOT проверять фасады на нормы ГОСТ: только геометрию и структуру.

**Источник:** Чат 26–28.09 19 (стр. 141)

#### Scenario: Правила валидатора
- GIVEN список правил валидатора
- WHEN его сверяют с ГОСТ
- THEN правил из ГОСТ в нём нет

### Requirement: Калибровка допусков
Работа MUST калибровать допуски выравнивания и шага по распределению реальных фасадов — CMP и
размеченных коттеджей, — а не задавать на глаз.

**Источник:** Чат 26–28.09 4 (стр. 43)

#### Scenario: Допуск выравнивания
- GIVEN распределение ошибки выравнивания окон по этажу на CMP
- WHEN выбирают допуск предупреждения
- THEN допуск — квантиль этого распределения, записанный рядом с допуском

### Requirement: Пять групп метрик
Работа MUST оценивать метод по пяти группам метрик ТЗ: визуальное сходство (FID/KID растров),
геометрия (доля фасадов без ошибок валидатора), структура (выравнивание против реального
распределения), разнообразие, доля валидных векторных документов.

**Источник:** ТЗ 7.11 (стр. 34); Чат 26–28.09 4 (стр. 46–50)

#### Scenario: Таблица метрик
- GIVEN папка результатов метода на тесте
- WHEN считают метрики
- THEN в таблице по числу на каждую из пяти групп

### Requirement: Согласованность с планом
Работа MUST считать метрику согласованности с планом: проёмы на месте, в запретных зонах нет окон
модели, углы сходятся.

**Источник:** Чат 26–28.09 8 (стр. 103); решение агента 28.09.2026 — метрики сверх ТЗ: план и описание; решение агента 17.10.2026 — окно плана в запретной зоне — предупреждение

#### Scenario: Фасад с окном в запретной зоне
- GIVEN фасад, где одно окно, поставленное моделью, стоит в запретной зоне
- WHEN считают согласованность с планом
- THEN фасад не засчитан согласованным

### Requirement: Соответствие описанию
Работа MUST считать долю выполненных требований из текста; проверяет парсер чертежа, а не
детектор на растре.

**Источник:** Чат 26–28.09 4 (стр. 49)

#### Scenario: Два этажа в тексте
- GIVEN текст «two-storey house» и фасад с одним этажом
- WHEN парсер чертежа сверяет фасад с текстом
- THEN требование этажности не выполнено

### Requirement: SVD-метрика — вспомогательная
Работа MUST давать SVD-метрику Beyond Segmentation только вспомогательной колонкой рядом с числом
элементов и полнотой: пустая маска получает у неё идеальный счёт.

**Источник:** Чат 26–28.09 11 (стр. 114)

#### Scenario: Пустой фасад
- GIVEN фасад без окон
- WHEN считают SVD-метрику
- THEN она идеальна, а число элементов — 0, и это видно в соседней колонке

### Requirement: Базовые подходы
Работа MUST сравнить метод с базовыми подходами: правило GenPlan (окна — разрывы, одна высота на
дом), LLM без дообучения, растр + EvoVec, building_tools со случайными параметрами.

**Источник:** ТЗ 7.10 (стр. 33); Чат 26–28.09 10 (стр. 111); Чат 26–28.09 15 (стр. 131)

#### Scenario: Таблица сравнения
- GIVEN метрики метода и базовых подходов на одном тесте
- WHEN составляют таблицу
- THEN в ней четыре строки базовых подходов и строка метода

### Requirement: Ablation
Работа MUST провести ablation: свой формат против сырого SVG текстом, привязка к сетке, общие
параметры дома против независимых сторон, предобучение на синтетике, условие по плану,
архитектуры между собой.

**Источник:** ТЗ 7.12 (стр. 35); решение агента 28.09.2026 — состав ablation

#### Scenario: Без привязки к сетке
- GIVEN метод с привязкой к сетке и без неё
- WHEN считают метрики структуры
- THEN в таблице ablation обе строки

### Requirement: Основная таблица на реальном тесте
Работа MUST считать основную таблицу на тесте из реальных данных, а BuildingNet — отдельной
колонкой.

**Источник:** решение агента 29.09.2026 — тест только из реальных данных

#### Scenario: Колонки таблицы
- GIVEN метрики на реальном тесте и на BuildingNet
- WHEN составляют основную таблицу
- THEN BuildingNet — отдельная колонка

### Requirement: Метрики одной командой
Модуль оценки MUST считать все метрики одной командой на папке результатов и выдавать таблицу.

**Источник:** решение агента 28.09.2026 — метрики одной командой

#### Scenario: Папка результатов
- GIVEN папка с листами фасадов метода
- WHEN запускают команду метрик
- THEN выдана таблица всех групп метрик
