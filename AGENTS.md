# Диплом: генерация векторных чертежей фасадов зданий

ИТМО, 2026/27. Модуль, который по векторному плану дома и тексту строит все фасады дома
векторным чертежом в цвете; встаёт после GenPlan. Инженер и хозяин репозитория — Никон
Парвицкий; продакт — научруки: Валерия Ефимова (тема, ТЗ, защита) и Егор Баженов (ведёт
работу, GenPlan); агенты — Claude Code, Codex, Cursor. Стек — Python + PyTorch (ТЗ).

Здесь — только то, что агенту нужно до первого действия. Процедуры — `docs/agents/` и
`docs/shared/SDD.md` (как он ложится на диплом — его раздел «Диплом»), почему правила такие —
`docs/WHY.md`. Правило меняется PR с диффом; до слияния не действует.

Требования — только из [openspec/specs/](openspec/README.md), а не из `docs/incoming/`.
Как строим — `docs/dev-plan.md`. База знаний — [docs/](docs/README.md).

## Схема — держать в голове всегда

```

  4. раскладка стены: проёмы с рамами, зоны отделки, цоколь, карниз, пояса       [модель]
  5. привязка к сетке этажей и осей + валидатор; не прошло → заново              [код]
  6. лист фасадов: цвета из параметров, отметки, оси; SVG + JSON                 [код]
  7. окна из фасадов → 3D-конвертер GenPlan                          [позже, вместе с Егором]
РЕЖИМ 1 · глухой куб — окна ставит модель
РЕЖИМ 2 · окна из плана — модель достраивает остальное; меняются шаги 2–5
ОБУЧЕНИЕ И ОЦЕНКА: синтетика → реальные дома; метрики, сравнение с базовыми, ablation
КОЛЛЕГИ: планы многоквартирных → шаг 2
```

- **Часть Никона** — только фасадный модуль; GenPlan и 3D-конвертер — Егора, генерацию
  GenPlan не меняем (ждёт ответа Егора, gf#36). Итоговая 3D-модель — совместная.
- **Главная идея** — параметры дома общие для всех сторон, поэтому фасады сходятся на углах

  на шагах 1 и 4 стоят стабы с интерфейсом модели (gf#60).

## Роли

Продакт (научруки) — замысел и наблюдаемый результат: ТЗ, ответы на вопросы. Инженер (хозяин) —
путь до работающего метода: спеки, задачи, эксперименты, статус требований; спеку научруки
не согласуют. Агенты — код, тесты, разборы по задаче. Агент сам решает всё, что не меняет
наблюдаемое поведение; что меняет — вопрос научрукам (`openspec/README.md`), отправляет его
хозяин (`/to-supervisors`). **Егор ужимает скоуп под GenPlan, защита идёт по ТЗ Валерии**:
обзор литературы, ablation и пять групп метрик не отменяются тем, что Егор о них молчит.

## Ход работы

- **Ход заканчивается отчётом, а не вопросом.** Вопрос — только о том, что требует приказа
  (новая задача, приоритет, PR, push, сообщение научрукам), или о необратимом: один, с причиной.
  На вопрос хозяина — ответ, а не правка файлов; «давай подумаем» — не «да».
- **Лучший вариант — решение агента**: объявить его отдельной строкой и сделать.
- **Сначала ищем готовое** (GitHub, Papers with Code, HuggingFace, PyPI, статьи): живая ли репа,
  лицензия, воспроизводится ли. Ничего нет — записать, что и какими запросами искали:
  отсутствие работ — аргумент о новизне на защите. Найденное — хозяину до кода.
- **Факты — из первоисточника** (датасет, статья, код), не по памяти: в дипломе нет выдуманной
  ссылки или числа. В `docs/` факт помечен `[проверено]` (чем) или `[не проверено]`; гипотезы —
  в `tmp/` (не в git). Найденное — в тот же заход: по задаче — в низ её файла, общее — в
  `docs/*.md` (пойдёт в текст ВКР), выбор с причиной и отброшенным — `docs/decisions.md`.
- **«Работает», «готово» — только после запуска.** Не запускал — так и сказать, с причиной.
  Оговорка вместо проверки («пока», «упрощённо», «заглушка») — не ответ.
- **Картинку смотреть глазами** тем же путём, каким смотрит хозяин (смотрелка).
- **У проверки есть случай, на котором она падает**: написал тест — сломать код, увидеть
  красное; откатить обратной правкой, не `git checkout` файла.
- **Три неудачные попытки — стоп**: четвёртую не делать. Первой строкой — что чинил, три
  попытки с результатом, какая дыра в коде, доке или спеке и как её закрыть. Попытки — в
  «Тупики» задачи.
- **Путаница — чинить источник, а не ответ**: знание — в репо, неверный источник — исправить.
- **Сначала кратчайший путь** до работающего целого; улучшения — после того, как хозяин его увидел.
- Задача с проверяемым «Готово, когда» — до конца, без промежуточных отчётов.

## Задачи

Задачи GitHub — копией в `docs/tasks/gf-0012.md` (префикс — `.backlog.json`), скрипт
`tools/backlog.py`. Устройство файла задачи и порядок — [docs/agents/tasks.md](docs/agents/tasks.md).

1. **Задача — до работы, по слову хозяина.** Сначала `grep -ri <слово> docs/tasks/`. Нашлась —
   работать по ней. Нет — спросить одной строкой «Завожу задачу „<название>“?»; просьба
   сделать работу — не разрешение. «Да» — черновик `docs/tasks/draft-<имя>.md` и
   `python3 tools/backlog.py new <черновик> --confirm`. «Нет» — отчёт в ответе, знание — в
   `docs/`. Отчёт длиннее пары абзацев — повод спросить. Находка по ходу — в «Что осталось».
2. **Начиная** — `python3 tools/backlog.py resume <номер>`, низ файла; ветка или своё дерево
   (`git worktree`) и `git ticket <номер>`; строка «Локальный повтор» — до кода.
3. **По ходу** — дописывать низ файла задачи; прерываясь — «Чем возобновлять».
4. **Коммит** — `<тип>[(область)]: <описание>` по Conventional Commits (`docs/agents/tasks.md`);
   хук `commit-msg` проверяет форму и дописывает «Implements gf#N»; **никогда close, fix,
   resolve рядом с номером** — задачу закрывает хозяин (`tools/closing_words.py`).
5. **Сдача** — PR, в описании «Implements gf#N» и «Описание продукта не затронуто» либо правка
   спеки, затем `gh pr merge <номер> --auto --merge`: CI гоняет `sh tools/check.sh`, проверка
   `check` обязательна для `main`, GitHub сливает сам. Красный CI — чинить в том же PR.
6. **Сделано** — сводка из пяти пунктов комментарием, «Первый промпт» в низ; закрывает
   хозяин, не слияние. Слит — `backlog.py sync`, копии задач — PR учёта `chore(backlog)`.

## Границы действий

Читать, измерять, диагностировать — свободно. Запись наружу (GitHub, Telegram научрукам) —
по «да» хозяина. Сторожа `.agents/guards/` перехватывают команды до выполнения во всех трёх
средах: запись в GitHub и `git push` без «да», PR без «Локального повтора», чтение `.env`,
закрывающие слова. Git-хуки (`templates/githooks/`, `sh tools/install_hooks.sh` после клона):
`pre-commit` — ключи в индексе (gitleaks) и `check.sh --quick`, `commit-msg` — форма и номер
задачи; CI повторяет оба по коммитам PR. Состояние обвязки — `python3 tools/harness.py`.

## Ключи и деньги

- Ключи — только в `.env` (в `.gitignore`; в git — `.env.example` без значений). Ключ, попавший
  в код, задачу, коммит, журнал или чат, — скомпрометирован: сказать хозяину сразу.
- Платный запрос — сначала сказать, сколько их будет, и прогнать на одном-двух. Тесты в
  платный API не ходят: вызов подменяется заглушкой.

## Команды
