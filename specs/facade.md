> Владелец дельт: Никон Парвицкий.

Как фасад устроен внутри модуля и что модуль отдаёт наружу. Главное свойство:
все фасады одного дома сходятся на углах по построению.

## Сущности

### HouseSpec

Параметры, общие для всех сторон дома.

| Поле | Значение |
|---|---|
| `building_type` | `cottage` \| `apartment` |
| `floors` | число надземных этажей |
| `floor_heights_m` | высота каждого этажа |
| `plinth_m` | высота цоколя |
| `eaves_m` | отметка карниза |
| `roof` | `Roof` |
| `style` | стиль из текста: современный, скандинавский, шале, классика… *(дельта 28.09)* |
| `materials` | палитра дома: какие материалы и цвета есть (штукатурка, дерево, камень, металл…); зоны и элементы ссылаются на неё *(дельта 28.09)*; материал — `id`, вид из библиотеки, цвет; без цвета — цвет вида из библиотеки `genfacade/config/library.toml` *(дельта 29.09, gf#11)* |

### Roof

| Поле | Значение |
|---|---|
| `kind` | `flat` — пока только плоская; скатные (`gable`, `hip`, `shed` с уклоном, осью конька, свесом) — на этапе модели *(хозяин 01.10, gf#64)* |
| `material` | покрытие из палитры `HouseSpec` *(дельта 29.09, gf#11)*; у плоской крыши на фасаде не видно |

### SideFacade

Фасад одной стороны `Side` (plan-input.md).

| Поле | Значение |
|---|---|
| `side` | ссылка на сторону |
| `elements` | элементы — `Element` |
| `zones` | зоны отделки — `MaterialZone` *(дельта 28.09)* |
| `silhouette` | прямоугольник стены: длина стороны × высота до карниза; вычисляется из `HouseSpec` и стороны (шаг 3), не генерируется. Видимая крыша и фронтон — с появлением скатных крыш *(хозяин 01.10, gf#64)* |

### Element

| Поле | Значение |
|---|---|
| `cls` | класс: 11 классов объектов CMP (`window`, `pillar`, `sill`, `blind`, `deco`, `cornice`, `balcony`, `molding`, `shop`, `facade`, `door`; двенадцатый класс CMP — фон масок) + для коттеджей `garage_door`, `porch`, `chimney` `DECISION 2026-09-28` |
| `id` | уникален на стороне; на него ссылается `parent` *(дельта 29.09, gf#11)* |
| `x_m`, `y_m`, `w_m`, `h_m` | осевой прямоугольник в метрах; `y` от отметки нуля вверх; нуль — уровень земли, цоколь от 0 до `plinth_m` `DECISION 2026-09-29` |
| `floor` | номер этажа |
| `parent` | вложенность: подоконник и ставни — у окна |
| `material` | переопределение материала из палитры `HouseSpec`, если нужно |
| `variant` | для проёмов: обычное, панорамное в пол, угловое, ленточное; деление рамы на створки *(дельта 28.09)* — `kind` + столбцы × ряды (`cols`, `rows`) *(дельта 29.09, gf#11)* |
| `fixed` | какие поля заданы условием, а не моделью: в режиме 2 у проёма из плана — `x_m`, `w_m` (маска, generation.md п. 4) *(дельта 29.09)* |

### MaterialZone

Участок стены с одним материалом: цоколь, основная отделка, акцентная зона.

| Поле | Значение |
|---|---|
| `shape` | многоугольник в координатах стены, метры |
| `material` | ссылка на материал из палитры `HouseSpec` |
| `role` | `plinth` \| `main` \| `accent` \| `band` (пояс, карниз) |

### FacadeSheet

Результат запроса.

| Поле | Значение |
|---|---|
| `spec` | `HouseSpec` |
| `facades` | `SideFacade` на каждую сторону |
| `svg` | лист всех фасадов — файл `sheet.svg`, получается из объекта |
| `json` | то же содержимое машиночитаемо — файл `sheet.json`, сам объект *(дельта 29.09, gf#11: `svg` и `json` — файлы выхода, а не поля)* |

## Правила

1. Элемент — класс плюс осевой прямоугольник, как в разметке CMP и в `Element`
   Facades-3D *(docs/decisions.md, 25.09)*.
2. Этажность, высоты, карниз, крыша и материалы задаются один раз в `HouseSpec`
   и одинаковы для всех сторон; по сторонам генерируются только элементы.
   `DECISION 2026-09-28` — главная идея согласованности, вынесена научрукам.
3. Стена — прямоугольник до карниза: её строит развёртка (шаг 3), раскладка и валидатор
   работают в нём *(хозяин 30.09, gf#62)*. Крыша пока только плоская, на фасаде её не видно;
   фронтон и скаты появятся на листе вместе со скатными крышами на этапе модели *(хозяин
   01.10, gf#64)*.
4. «В цвете» на первом этапе — цвет и материал из фиксированной
   библиотеки; модель решает, **где** какая зона и какой материал из палитры
   дома, но не придумывает новые цвета *(дельта 28.09)*. Библиотека (кирпич, штукатурка, сайдинг, дерево, металлочерепица и т. п.);
   генерация текстур — позже *(хозяин 28.09)*.
5. SVG: каждый элемент — `<rect>` или `<polygon>` с атрибутом класса
   (`data-cls`) и материала; координаты — в метрах в едином масштабе листа.
   `DECISION 2026-09-28`.
6. Лист фасадов оформляется как в эскизном проекте ИЖС: фасады в осях,
   отметки уровней (ноль, цоколь, этажи, карниз; конёк — со скатными крышами)
   *(ориентир показан научрукам 28.09)*.
7. JSON содержит ровно то же, что SVG; SVG получается из JSON детерминированно.
8. Совместимость с CAD — через экспорт SVG в DXF готовой библиотекой;
   своего конвертера не пишем. `DECISION 2026-09-28`.

9. **Состав фасада по уровням** *(подтвердил хозяин 28.09)*:
   1) проёмы с типом (обычное, панорамное, угловое…) и делением рам, двери,
      гаражные ворота;
   2) зоны отделки, цоколь, подоконники, наличники, карниз, пояса;
   3) выступающие элементы: крыльцо, козырёк, балкон, терраса, навес.
   Цель работы — уровни 1–2, уровень 3 — расширение. Крыша — в `HouseSpec`,
   её силуэт считает код. Высоты цоколя и карниза тоже задаёт `HouseSpec`
   (одни на дом); модель на стене решает только, есть ли зона или элемент
   и из какого материала палитры — иначе углы не сойдутся *(дельта 29.09)*.

## Критерии приёмки

- На углах дома у соседних фасадов совпадают отметки этажей и карниза.
- JSON → SVG → разбор SVG → JSON даёт тот же набор элементов.
- Размеченный фасад CMP переводится в `SideFacade` и обратно без потерь классов
  и координат (с точностью квантования).
- SVG открывается в Inkscape и конвертируется в DXF без ошибок — проверяется ближе
  к защите, не на этапе 0 *(хозяин 29.09)*; см. «Открыто».

  как концепт (в Facades-3D есть `FloorConcept`).
