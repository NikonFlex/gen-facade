# Вход: план дома и препроцессор

> **Статус: provisional.** Собрано агентом 28.09.2026.
> Источники: docs/incoming/Переписка в Telegram 26–28.09.md (ответ Егора на семь вопросов о формате плана, 28.09 20:21;
> пример плана test3.svg от Егора); код GenPlan HEAD 2ed651c — docs/tasks/gf-0034.md, gf-0036.md;
> пример `materials/genplan-plan-example.svg`; docs/incoming/Сообщение научрукам и ответы 29.09.md (запрос примеров планов МКД).
> Владелец дельт: Никон Парвицкий.

Во что превращается план на входе, прежде чем по нему строить фасады.
План приходит из разных систем (GenPlan для коттеджей, коллеги для МКД),
поэтому внутри модуля он хранится в своём формате, не привязанном к GenPlan.

## Сущности

### Plan

План этажа во внутреннем формате модуля. Координаты — метры в осях плана,
y вверх (в SVG y вниз — препроцессор переворачивает) *(дельта 30.09, gf#14)*.

| Поле | Значение |
|---|---|
| `walls` | стены — осевые прямоугольники `Rect`, как в источнике; перекрытия сливает препроцессор, в `walls` они остаются *(дельта 30.09)* |
| `outline` | наружный контур, замкнутый многоугольник по часовой стрелке |
| `openings` | все проёмы в координатах плана — `PlanOpening` *(дельта 30.09)* |
| `sides` | стороны контура — `Side`; заполняет препроцессор *(дельта 30.09)* |
| `scale_m_per_px` | масштаб, метры на пиксель источника — чтобы вернуться к координатам SVG |
| `source` | `genplan` \| `mkd` \| `synthetic` \| `buildingnet` \| `bio` \| `manual` — откуда пришёл (последние три — для обучения и теста, data.md) |

### Rect

Осевой прямоугольник в плане: `x0_m < x1_m`, `y0_m < y1_m`.

### PlanOpening

Проём в координатах плана *(дельта 30.09)*. На стороне ему соответствует `Opening`
с координатой вдоль стороны.

| Поле | Значение |
|---|---|
| `kind` | `window` \| `door` \| `entrance` |
| `rect` | `Rect` — где проём в плане |
| `external` | на наружном контуре |
| `sealed` | заделан в глухом режиме: на фасаде его нет, в `walls` на его месте стена |

### Side

Одна сторона наружного контура; по ней строится один фасад.

| Поле | Значение |
|---|---|
| `index` | номер по часовой стрелке от стороны входа |
| `length_m` | длина |
| `orientation` | направление наружной нормали |
| `openings` | проёмы этой стороны, координата — вдоль стороны от её левого края, если смотреть снаружи |
| `forbidden` | запретные зоны — `ForbiddenZone` |
| `has_entrance` | на стороне входная дверь |

### Opening

| Поле | Значение |
|---|---|
| `kind` | `window` \| `door` \| `entrance` |
| `x_m`, `width_m` | положение и ширина вдоль стороны |
| `external` | на наружной стене |

### ForbiddenZone

Интервал `[x0_m, x1_m]` вдоль стороны, где к наружной стене примыкает внутренняя.
Внутренние стены GenPlan часто прорисованы насквозь до наружной грани — наружной
считается только стена, вытянутая вдоль стороны *(дельта 30.09, gf#14)*.

## Правила

1. **Формат GenPlan** *(научруки 28.09, сверено с кодом)*: SVG из осевых `<rect>`
   в пикселях; класс задан цветом — стены `#000000`, окна `#99ccff`, двери —
   створкой и дугой (ниже); прямоугольники стен перекрываются; наружный контур не помечен;
   типов комнат нет; этаж один.
   Уточнено по коду GenPlan HEAD 2ed651c (`decorator/decoration.py`,
   `dto/opened_door/opened_door.py`) и примеру `materials/genplan-plan-example.svg`
   *(дельта 30.09, gf#14)*: окна — прямоугольники `#99ccff`, вписанные в разрыв стены;
   **все двери** в 2D SVG, и вход, и внутренние, — пустой разрыв и открытая створка:
   **чёрный** `<rect>` 5 px (у положения UP без `fill`, то есть тоже чёрный) и дуга
   `<path>` из петли. Коричневый цвет двери — только в 3D. Створку по цвету не отличить
   от стены — её узнают по дуге и размеру и выкидывают из стен. Бывают и планы только
   из стен, до decorator GenPlan (`examples/svgs/test1`, `test2` в их репо) — тогда
   проёмы только по разрывам.
2. Координаты GenPlan — пиксели, «масштабируемая графика, не привязываться»
   *(научруки 28.09)*. Масштаб — по ширине входа: 0.9 м, как в 3D-конвертере GenPlan
   (`DEFAULT_DOOR_WIDTH = 90`, `three_dimensional/convertor.py:32, 249`), чтобы фасад
   сошёлся с его 3D-моделью. Высота стены из текста (250 / 275 / 300 см, `WallSizeType`)
   у GenPlan задаёт только высоту стены, не масштаб плана — у нас она идёт в `HouseSpec`
   *(дельта 30.09, gf#14: сверено с кодом; прежняя формулировка «масштаб по высоте стены»
   к коду не сводится)*. `DECISION 2026-09-28`.
3. Этажность и крыша в плане отсутствуют и берутся из текста.
4. Препроцессор: сливает перекрывающиеся стены → находит наружный контур →
   режет на стороны → проецирует на каждую проёмы → отмечает запретные зоны →
   переводит в метры.
5. Окно — это разрыв между двумя соосными стенами на наружном контуре;
   самый узкий наружный разрыв — входная дверь. Так делает GenPlan (`decorator`),
   так же читаем и мы, но свой код: у их правила ложные проёмы между
   противоположными стенами равной длины (gf#36).
   Прямоугольник окна или двери из SVG — подсказка типа, но не основание для проёма:
   проём есть, только если прямоугольник лежит в разрыве наружного контура. Разрыв
   с дугой двери — дверь; вход — самая узкая дверь на наружном контуре, а если
   наружных дверей нет — самый узкий наружный разрыв *(дельта 30.09, gf#14)*.
   Соосные стены — перекрывающиеся не меньше чем на половину толщины; разрыв между ними
   закрывает только стена, пересекающая его на всю толщину. Стена, которая лишь заходит
   в полосу окна, разрыв не закрывает — это дефект из «Открыто», проём остаётся, поверх
   него — запретная зона. Наружный разрыв без створки — окно, как у GenPlan; внутренний
   без створки — проход, не проём. Разрывы короче порога (`config/plan.toml`) — швы
   векторизации *(дельта 30.09, gf#14)*.
6. Режим без референсов: наружные разрывы, кроме входной двери, заделываются —
   стены по обе стороны сливаются. `DECISION 2026-09-28` (docs/decisions.md).
7. Дефектный план (контур не замкнулся, нет входа) не чинится молча: препроцессор
   возвращает причину отказа.

## Критерии приёмки

- На простом доме `tests/fixtures/simple_house.svg` (10 × 5 м, план нарисован кодом GenPlan;
  до gf#58 — на примере `materials/genplan-plan-example.svg`) находится замкнутый контур, четыре стороны
  и все проёмы из SVG с точностью до 2 px.
- На синтетической коробке из четырёх стен без разрывов не появляется
  ни одного проёма (у правила GenPlan здесь два ложных).
- В режиме без референсов у результата ровно один наружный проём — вход.
- План без входной двери отклоняется с понятной причиной.
