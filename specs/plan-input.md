# Вход: план дома и препроцессор

> **Статус: provisional.** Собрано агентом 28.09.2026.
> Источники: docs/incoming/Переписка в Telegram 26–28.09.md (ответ Егора на семь вопросов о формате плана, 28.09 20:21;
> пример плана test3.svg от Егора); код GenPlan HEAD 2ed651c — docs/tasks/gf-0034.md, gf-0036.md;
> пример `materials/genplan-plan-example.svg`.
> Владелец дельт: Никон Парвицкий.

Во что превращается план на входе, прежде чем по нему строить фасады.
План приходит из разных систем (GenPlan для коттеджей, коллеги для МКД),
поэтому внутри модуля он хранится в своём формате, не привязанном к GenPlan.

## Сущности

### Plan

План этажа во внутреннем формате модуля.

| Поле | Значение |
|---|---|
| `walls` | стены: осевые прямоугольники после слияния перекрытий |
| `outline` | наружный контур, замкнутый многоугольник по часовой стрелке |
| `openings` | все проёмы — `Opening` |
| `scale_m_per_px` | масштаб, метры на пиксель |
| `source` | `genplan` \| `mkd` \| `synthetic` — откуда пришёл |

### Side

Одна сторона наружного контура; по ней строится один фасад.

| Поле | Значение |
|---|---|
| `index` | номер по часовой стрелке от стороны входа |
| `length_m` | длина |
| `orientation` | направление наружной нормали |
| `openings` | проёмы этой стороны, координата — вдоль стороны от её левого края, если смотреть снаружи |
| `forbidden` | запретные зоны — `ForbiddenZone` |
| `has_entrance` | на стороне входная дверь |

### Opening

| Поле | Значение |
|---|---|
| `kind` | `window` \| `door` \| `entrance` |
| `x_m`, `width_m` | положение и ширина вдоль стороны |
| `external` | на наружной стене |

### ForbiddenZone

Интервал `[x0_m, x1_m]` вдоль стороны, где к наружной стене примыкает внутренняя.

## Правила

1. **Формат GenPlan** *(научруки 28.09, сверено с кодом)*: SVG из осевых `<rect>`
   в пикселях; класс задан цветом — стены `#000000`, окна `#99ccff`, двери —
   коричневым и дугой; прямоугольники стен перекрываются; наружный контур не помечен;
   типов комнат нет; этаж один.
2. Координаты GenPlan — пиксели, «масштабируемая графика, не привязываться»
   *(научруки 28.09)*. Масштаб задаётся высотой стены из текста (2.5 / 2.7 / 3 м)
   *(научруки 28.09)*; если высоты нет — по ширине входной двери 0.9 м, как в
   конвертере GenPlan. `DECISION 2026-09-28`.
3. Этажность и крыша в плане отсутствуют и берутся из текста.
4. Препроцессор: сливает перекрывающиеся стены → находит наружный контур →
   режет на стороны → проецирует на каждую проёмы → отмечает запретные зоны →
   переводит в метры.
5. Окно — это разрыв между двумя соосными стенами на наружном контуре;
   самый узкий наружный разрыв — входная дверь. Так делает GenPlan (`decorator`),
   так же читаем и мы, но свой код: у их правила ложные проёмы между
   противоположными стенами равной длины (gf#36).
6. Режим без референсов: наружные разрывы, кроме входной двери, заделываются —
   стены по обе стороны сливаются. `DECISION 2026-09-28` (docs/decisions.md).
7. Дефектный план (контур не замкнулся, нет входа) не чинится молча: препроцессор
   возвращает причину отказа.

## Критерии приёмки

- На `materials/genplan-plan-example.svg` находится замкнутый контур, четыре стороны
  и все проёмы из SVG с точностью до 2 px.
- На синтетической коробке из четырёх стен без разрывов не появляется
  ни одного проёма (у правила GenPlan здесь два ложных).
- В режиме без референсов у результата ровно один наружный проём — вход.
- План без входной двери отклоняется с понятной причиной.

- Этажность МКД-плана: один план на этаж или типовой этаж.
- Непрямоугольные контуры (эркеры, Г-образные дома): сколько сторон считать
  отдельными фасадами.
