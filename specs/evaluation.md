> **Статус: provisional.** Собрано агентом 28.09.2026.
> Источники: docs/incoming/ТЗ Валерии и заметка Егора.md (пп. 9–12, пять групп метрик);
> docs/metrics.md (разбор SVD-метрики Beyond Segmentation, gf#30); docs/plan.md §7.
> Владелец дельт: Никон Парвицкий.

Как проверяем, что фасад правильный и что метод лучше базовых подходов.

## Сущности

### Violation

Нарушение, найденное валидатором.

| Поле | Значение |
|---|---|
| `rule` | код правила |
| `severity` | `error` \| `warning` |
| `side`, `element` | где |
| `message` | по-человечески |

## Правила

1. **Валидатор** принимает `FacadeSheet` или SVG и выдаёт список `Violation`.
   Ошибки: SVG не разбирается; элемент вне силуэта стены; проёмы пересекаются;
   окно в запретной зоне; в режиме с референсами проём плана отсутствует
   или смещён; на углах не совпадают отметки. Предупреждения: нарушения
   выравнивания и шага сверх допуска.
2. Допуски выравнивания и шага калибруются по распределению реальных фасадов
   (CMP, размеченные коттеджи), а не задаются «на глаз».
3. **Метрики** — пять групп ТЗ и две наши:

   | Группа | Метрика |
   |---|---|
   | визуальное сходство | FID/KID по растеризованным фасадам против растеризованной реальной разметки |
   | геометрия | доля фасадов без ошибок валидатора; ошибок на фасад |
   | структура | ошибка выравнивания по этажам и осям, стабильность шага — относительно реального распределения |
   | разнообразие | попарное расстояние между образцами при одном условии; покрытие |
   | валидные документы | доля SVG, которые разбираются и проходят валидатор |
   | согласованность с планом | проёмы на месте, запретные зоны пусты, углы сходятся |
   | соответствие описанию | доля выполненных требований из текста; проверяет парсер чертежа, а не детектор |

4. SVD-метрика Beyond Segmentation — только вспомогательной колонкой рядом
   с числом элементов и полнотой: у неё вырожденный оптимум (пустая маска
   и один прямоугольник получают ноль; выбросить 90% окон выгоднее, чем выровнять),
   проверено своей реализацией, gf#30.
5. **Базовые подходы:** правило GenPlan (окна = разрывы, одна высота на дом);
   LLM без дообучения по плану и тексту; растр + EvoVec; building_tools
   со случайными параметрами под текст.
6. **Ablation:** наш формат против сырого SVG как текста; привязка к сетке;
   общий `HouseSpec` против независимых сторон; предобучение на синтетике;
   условие по плану; архитектуры между собой (generation.md).
7. Все числа — на тестовом наборе из реальных данных (data.md, правило 5).

## Критерии приёмки

- Валидатор ловит каждое правило из п. 1 на специально испорченном примере
  и молчит на эталонной разметке CMP (без ошибок; предупреждения допустимы).
- Все метрики считаются одной командой на папке результатов и выдают таблицу.
- У каждой метрики есть тест, который падает на подменённом входе.
