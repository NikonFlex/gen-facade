## Сущности

### Sample

Один обучающий или тестовый пример.

| Поле | Значение |
|---|---|
| `id` | имя примера, уникально внутри источника; оно же имя файла *(дельта 01.10, gf#28)* |
| `plan` | `Plan` (plan-input.md) или `null`, если источник без плана (CMP) |
| `sheet` | `FacadeSheet` (facade.md) — эталон |
| `texts` | описания: каждое — вид (`template` \| `paraphrase` \| `manual`) и текст *(дельта 01.10, gf#28)* |
| `source` | `buildingnet` \| `synthetic` \| `bio` \| `manual` \| `cmp` \| `hznu` \| `lod3` \| `lsaa` |
| `split` | `train` \| `val` \| `test` |

## Правила

1. **Синтетика** — свой генератор на Python *(хозяин 01.10; прежде — building_tools: он даёт
   только контур и операции моделирования, правил расстановки и внутренних стен в нём нет)*:
   случайный план в формате GenPlan → препроцессор (plan-input.md) → параметры дома и раскладка
   стен правилами → пары «план + все фасады» с точной разметкой. Крыша плоская. Идёт
   на предобучение. Числа генератора — в конфиге.
   Глухие стены генератор делает **намеренно** — торец, стена с гаражом, на ступени 3 короткие
   уступы, — иначе модель выучит «на каждой стене ряд окон» *(хозяин 01.10, generation.md,
   правило 11)*. Доля глухих стен — в описи.
2. **CMP Facade** — многоквартирные *(хозяин 28.09: «CMP подходит»)*. 606 фасадов,
   прямоугольники классов. Планов и других сторон нет: `plan = null`, режим
   с референсами моделируется по разметке — горизонтали окон берутся как заданные.
   Ловушка формата: тег `<x>` в CMP — вертикальная ось (`tools/cmp.py`).
3. **Solar Decathlon** — реальные коттеджи с планами и фасадами: 30 домов
   в public domain, 69 листов фасадов (gf#26). Семантики нет, разметка вручную.
   Только тест и дообучение.
4. **Данные лаборатории** — это 306 растровых рендеров **коттеджей** без
   разметки, присланные Егором (gf#33). Городского датасета «растр от векторных
   фасадов», о котором говорила Валерия 28.09, не существует *(дельта 29.09, gf#33,
   хозяин 29.09: Валерия ошиблась, такого датасета у лаборатории нет)*. Рендеры — для материалов, цвета и ручной разметки коттеджей;
   публикация производного — после выяснения прав.
5. Тест — только реальные данные (ручная разметка чертежей и рендеров);
   синтетика в тест не входит. BuildingNet — модели, сделанные людьми, а не обмеры:
   его test split — отдельный второй тест (evaluation.md, правило 7). Состав —
   раздел «Состав датасета» выше. **SYNBUILD-3D не берём**: фасады вырожденные
   (окно и подоконник = 1/3 этажа, двери на верхних этажах) `[проверено 29.09]`.
6. Описания синтезируются из разметки по шаблонам (этажность, число окон, крыша,
   материалы), перефразируются LLM; часть теста — описания, написанные вручную,
   чтобы модель не выучила шаблон.
7. Данные в git не кладутся (`data/` в `.gitignore`); в git — скрипты получения
   и описи. Большие данные собираются и лежат на отдельной машине; корень данных — настройка
   (`genfacade/config/data.toml`) *(хозяин 01.10)*.
8. **Стена в примере — прямоугольник до карниза** *(хозяин 01.10)*: крыша в данных плоская, как
   в формате (facade.md, правило 3). У реальных домов со скатной крышей всё выше карниза
   отбрасывается; в описи источника — исходный вид крыши и число срезанных элементов.
9. **Ступени данных и обучения** *(хозяин 01.10)*: прямоугольный дом с окнами из плана →
   тот же дом в глухом режиме → непрямоугольные контуры. Данные первых двух ступеней одни:
   режимы различаются тем, заданы ли на входе положение и ширина окон (facade.md, `fixed`).
10. Пример хранится файлом `<корень>/<источник>/<id>.json`; опись источника —
    `<корень>/<источник>/_manifest.json`: число примеров, разбиение, число стен и элементов
    по классам, дата, коммит *(дельта 01.10, gf#28)*.
11. **Сборка синтетики** *(дельта 01.10, gf#28)*: дома по seed подряд; часть (`train` / `val`) зависит
    только от seed; прерванная сборка продолжается с готовых домов; дом с ошибкой валидатора
    не пишется и перечислен в описи; настройки генератора и коммит записаны рядом
    (`_build.json`) — с другими настройками или кодом в ту же папку сборка не продолжается.

## Критерии приёмки

- Для каждого источника есть скрипт, который воспроизводимо собирает `Sample`
  с опись-файлом (число примеров, классы, разбиение).
- Ни один дом не попадает одновременно в `train` и `test`: Solar Decathlon,
  FreeFarmhouse — по дому; BuildingNet — по его официальным splits.
- Шаблонное описание и эталон согласованы: парсер описания на эталонном
  фасаде даёт 100% выполненных требований.

## Открыто

  моделей (12 проверены глазами, gf#40). Нет словаря сопоставления имён с палитрой.

- Откуда присланные рендеры коттеджей и какие у них права (водяной знак).
- Сколько синтетики: 10 тысяч домов — порядок, проверить по кривой обучения.
- Источник планов для ступени непрямоугольных контуров: ProcTHOR-10k, свой генератор комнат
  или CubiCasa5k (docs/datasets.md, «Планы домов для синтетики»).
