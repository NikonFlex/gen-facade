## Правила

1. Конвейер из семи шагов: модель — шаги 1 и 4, остальное код *(дельта 28.09,
   решение хозяина; схема — docs/assets/facade-modules.png; одобрили научруки 29.09)*:
   1) текст → `HouseSpec`; 2) план → препроцессор: стороны, заделанные разрывы
   (глухой режим), запретные зоны, метры; 3) развёртка: прямоугольник каждой
   стены — длина стороны из плана, высота до карниза из `HouseSpec`, детерминированно,
   без крыши *(хозяин 30.09, gf#62)*; 4) модель ставит элементы на каждую стену;
   5) разбор ответа → привязка к сетке → валидатор, брак — генерировать заново;
   6) лист фасадов: цвета, отметки уровней и оси — оформление только здесь, на шагах
   3–5 его нет *(хозяин 30.09, gf#62)*; крыша пока только плоская *(хозяин 01.10, gf#64)*;
   7) позже — окна из `FacadeSheet` в 3D-конвертер GenPlan (integration.md).
   «Брак — генерировать заново» — с моделью: стаб детерминирован, повтор дал бы то же
   самое; до модели нарушения только записываются в трассу *(хозяин 30.09)*.
2. **Разбор текста** в `HouseSpec` — отдельный шаг, его делает модель *(решение
   хозяина 28.09)*; до модели — правило. Через этот шаг работает условная
   генерация по параметрам (ТЗ, п. 8): `HouseSpec` можно задать без текста.
   До модели на шаге 1 — стаб с интерфейсом модели (`genfacade/models/stub.py`): на любой текст
   одна и та же `HouseSpec` из `models/stub_data/house.json` (один этаж, плоская крыша, палитра
   по ролям `main`, `plinth`, `accent`, `trim`, `roof`); текст сохраняется в запросе. Парсер по
   словам не пишем — модель его заменит *(хозяин 30.09, gf#51, gf#60)*.
3. **Генератор** выдаёт раскладку одной стороны последовательностью токенов на
   квантованной сетке: элементы «класс, вариант, x, y, w, h» (вариант — тип проёма
   и деление рамы) и зоны отделки «роль, материал из палитры, многоугольник»
   (facade.md, `Element`, `MaterialZone`) *(дельта 29.09)*. Условия: `HouseSpec`, `Side`
   (длина, проёмы, запретные зоны), текст.
   Стены одного дома идут **одной последовательностью** по обходу контура: к очередной стене
   модель видит уже разложенные — так согласуются типы окон, деление рам, ритм и акцентная
   отделка, которых нет в `HouseSpec` *(хозяин 01.10, docs/decisions.md)*. Одиночный фасад без
   остальных сторон (CMP) — дом из одной стены.
   **Запись токенами** *(дельта 01.10, `genfacade/train/tokens.py`)*: условие — режим,
   параметры дома, палитра и по каждой стене длина, отметка входа, запретные зоны, проёмы
   плана; ответ — по каждой стене элементы, затем зоны. Стены — в порядке сторон плана,
   от стороны входа по обходу контура. Элементы — в порядке отрисовки (наличник раньше своего
   окна). Числа — целые шаги сетки 5 см (`config/tokens.toml`); на сетку встают края элемента,
   размер — их разность. Имена элементов не пишутся: родитель — номер элемента в стене.
   Негодный ответ разбор не чинит — отказывает с причиной. `DECISION 2026-10-01`.
4. Режимы отличаются только входом *(Егор 28.09)*: в режиме с референсами
   горизонтальные положения и ширины проёмов заданы, модель достраивает
   высоты проёмов, зоны отделки и декор; в режиме без референсов ставит и проёмы.
   Этажность задаёт не модель шага 4, а `HouseSpec` (шаг 1) *(дельта 29.09)*.
   На схеме режимы названы «режим 1 · глухой куб» (без референсов, `blind`) и
   «режим 2 · окна из плана» (с референсами, `with_openings`).
   Представление одно на оба режима: заданные проёмы режима 2 — условие
   (маска) поверх той же последовательности элементов, что в режиме 1.
   Модель и метрики — сначала для режима 2, затем для режима 1 *(хозяин 29.09,
   docs/decisions.md)*.
   До модели на шаге 4 — стаб с интерфейсом модели (`genfacade/models/stub.py`): для каждой
   стены отдаёт заготовленные элементы и зоны простого дома (`models/stub_data/facades.json`,
   один набор на оба режима); на плане, которого стаб не знает, — отказ с причиной. Заготовку
   один раз сделало правило раскладки (gf#50: окна из плана, высоты долями этажа как
   `WindowSizeType` GenPlan, подоконники, карниз, зоны), потом правило удалено *(хозяин 30.09,
   gf#60)*. В режиме без референсов стаб окна не расставляет — критерий про запретные зоны
   проверяется на модели.
5. Кандидаты архитектуры сравниваются между собой (ТЗ, п. 5: «в том числе
   трансформеры и на основе графов»):
   - дообученная LLM (QLoRA на открытой модели), печатает элементы в компактном
     текстовом формате — рецепт дообучения есть в Text2SVG лаборатории;
   - свой компактный трансформер с предобучением на синтетике;
   - диффузия над множеством элементов с графом отношений (в духе LayoutDM,
     CVPR 2023, и GSDiff для планировок).
6. Путь «растровая генерация → векторизация EvoVec» (заметка Егора) —
   базовый подход в сравнении, не основной метод. `DECISION 2026-09-28`.
7. **Привязка к сетке** после генерации: элементы выравниваются по линиям
   этажей и вертикальным осям, соседние окна получают одинаковые координаты.
8. Все фасады дома генерируются при одном `HouseSpec`; согласованность углов
   обеспечивается им, а не моделью (facade.md, правило 2).
   Модель не придумывает цвета: палитра материалов — в `HouseSpec`, одна на дом.
   Модель раскладывает стену — проёмы, зоны отделки, декор — и для каждой зоны
   выбирает материал из палитры (facade.md, правила 4 и 9) *(дельта 28.09)*.
   Что `HouseSpec` не задаёт — характер стен, — согласуется общей последовательностью (правило 3).
9. Каждый запуск сохраняет рядом с результатом `.json` с моделью, `seed`,
   параметрами и датой (CLAUDE.md).
10. Каждый запуск сохраняет **трассу** — выход каждого шага 1–6 (JSON и SVG той же
    отрисовки, что у листа), чтобы любой шаг можно было посмотреть отдельно
    *(хозяин 29.09; раскладка файлов — docs/dev-plan.md)*.
11. **Стена без проёмов — допустимый ответ** *(хозяин 01.10)*: только зоны отделки. В режиме
    с референсами это решает план — нет разрыва, нет окна; модель проёмов не добавляет. В режиме
    без референсов решает модель по условиям: длина стены, запретные зоны, где вход, что стоит
    на уже разложенных стенах. Учится этому из данных (data.md, правило 1).

## Критерии приёмки

- Разбор текста: на ручном тестовом наборе описаний этажность и тип крыши
  извлекаются с точностью не ниже заданной в evaluation.md.
- Режим с референсами: все проёмы плана присутствуют на фасаде в тех же
  положениях (допуск — шаг квантования).
- Режим без референсов: ни одно окно не попадает в запретную зону.
- Один и тот же `seed` даёт тот же результат — критерий для модели (этап 4); правило до модели
  детерминировано: одинаковый вход — одинаковый результат *(хозяин 30.09)*.
